## Separate discovery work

- **PDF import:** allow 2–4 weeks for a proof of concept after deciding whether the feature extracts embedded tables, page text, scanned images with OCR, or a narrower subset. OCR and extraction confidence need their own UX and acceptance rules.
- **Full Power Query M compatibility:** allow 2–3 weeks to assess parser/runtime options and compatibility requirements after the query model is designed. A full M implementation is not included in the week 9–13 query-preparation phase; estimate it after the feasibility result.
- **Additional connectors:** after the connection foundation, estimate each connector at roughly 1–3 weeks depending on authentication, navigation, source-specific settings, and refresh. Maintain a prioritized connector list rather than assigning the same estimate to every catalog entry.

## Milestones

1. **Local import release — around weeks 1–13:** robust existing file import, multiple tables, broader local sources, and practical query preparation.
2. **Connected-source release — around weeks 16–25:** reusable connection management plus the first remote database, OData, and Web sources.
3. **Service and advanced-mode releases — week 26 onward:** gateway/scheduled refresh and DirectQuery, live, or Direct Lake only if the product scope includes their required services and runtime behavior.

The current project roadmap explicitly keeps service integrations out of scope. The first two milestones extend the local-first app; milestone 3 needs a product decision before implementation. The critical path is **reliable current import → multi-table project model → query model → connection/auth foundation → remote connectors → service refresh or alternate connection modes**.

## Planning assumptions and risks

- The current CSV, modern Excel, flat JSON, and regular-record XML workflows remain the baseline; `.xls` is counted under local source expansion.
- The 125-entry picker is a discovery catalog. Connector implementation should follow user priority and source-specific requirements.
- Folder combine, local Parquet, SQLite, and the core legacy `.xls` workflow passed lifecycle acceptance. Broader `.xls` real-world/error cases remain open. PDF extraction, connector authentication, and DirectQuery still need distinct parsing or runtime decisions.
- Power Query Online modules and Power BI Service administration are product/service surfaces. The native app can implement comparable workflows, but matching those services requires real service APIs and account access.
- Use this as an estimate and acceptance plan; update phase status as each implementation is completed and checked.
