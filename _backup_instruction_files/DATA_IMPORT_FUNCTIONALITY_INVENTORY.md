# Data Import Functionality Inventory

**Research date:** 2026-10-08. **Scope:** End-to-end Power BI Desktop Get Data / Power Query behavior, compared with the current Analytics Studio project. “A to Z” here means the full user journey from finding a source through loading and refreshing it. The repository is a native desktop app; Microsoft Learn is the web reference. Online authoring and Power BI Service behavior are separated below. Connector availability changes over time, so per-connector docs remain authoritative.

> This inventory is import-specific. The broader Power BI feature map and whole-product schedule are in [POWER_BI_FUNCTIONALITY_ROADMAP.md](</Users/armaan/Power BI tool/POWER_BI_FUNCTIONALITY_ROADMAP.md>).

## 1. Power BI Desktop: the full Get Data journey

Microsoft documents the shared Desktop sequence as **connection settings → authentication → data preview → query destination**, while warning that individual connectors may expose only some stages or use connector-specific screens. [Power Query Get Data overview](https://learn.microsoft.com/en-us/power-query/get-data-experience)

1. **Open Get Data and find a source.** Home offers common-source shortcuts and the full Get Data experience. The redesigned experience has Home, New, Recent data, OneLake catalog, Blank table, and Blank query sections; the original experience has the category-based dialog. Search and category browsing help locate sources. Microsoft currently labels the redesigned Desktop experience as Preview. [Get data in Power BI Desktop](https://learn.microsoft.com/en-us/power-bi/connect-data/desktop-data-sources)
2. **Choose a connector and check its support.** Desktop groups sources under File, Database, Microsoft Fabric, Power Platform, Azure, Online Services, and Other. File examples include Excel, Text/CSV, XML, JSON, Folder, PDF, Parquet, and SharePoint folder. Database, cloud, service, web, scripting, and driver connectors are also available. The global Power Query catalog spans several Microsoft products, so use the Desktop support matrix and each connector’s own capability, prerequisite, authentication, and mode documentation. Beta/Preview status and support can differ between Desktop and Service. [Desktop sources](https://learn.microsoft.com/en-us/power-bi/connect-data/desktop-data-sources), [Power Query connector catalog](https://learn.microsoft.com/en-us/power-query/connectors/), [Power BI source capabilities](https://learn.microsoft.com/en-us/power-bi/connect-data/power-bi-data-sources)
3. **Enter connection settings.** Depending on source, provide a local or web path, server, database, workspace/item, URL, or other required parameters. Some connectors expose advanced settings or allow a native query; others need no parameter. These controls vary by connector. [Get Data stages](https://learn.microsoft.com/en-us/power-query/get-data-experience)
4. **Authenticate and manage access.** The connector determines which sign-in methods are offered. Common examples include Anonymous, API key, Basic, Database, and organizational or Microsoft account sign-in; some connectors also expose methods such as Windows authentication. Desktop can reuse stored credentials and lets users edit or clear them under **File → Options and settings → Data source settings**. URL-level credential scope is connector-dependent. [Power Query authentication](https://learn.microsoft.com/en-us/power-query/connector-authentication)
5. **Set source privacy where relevant.** Desktop can assign a source a privacy level and apply settings globally or to the current file. Privacy levels govern how Power Query may combine data from different sources; ignoring them can expose private data. These controls matter when an import query combines sources. [Privacy levels in Power Query](https://learn.microsoft.com/en-us/power-bi/desktop-privacy-levels)
6. **Choose the connection path when offered.** **Import** copies selected data into the semantic model. Some supported connectors also offer **DirectQuery**, which leaves data at the source and issues queries as users interact. A **live connection** builds a report on an existing Power BI/Analysis Services model. **Direct Lake** is a separate Fabric/OneLake model path. These are different behaviors, and connector support is specific to each source. [Import and DirectQuery](https://learn.microsoft.com/en-us/power-bi/connect-data/desktop-use-directquery), [Live connection vs. DirectQuery](https://learn.microsoft.com/en-us/power-bi/connect-data/service-live-connect-dq-datasets), [Direct Lake](https://learn.microsoft.com/en-us/fabric/fundamentals/direct-lake-overview)
7. **Browse available objects and preview.** Depending on connector, Power BI shows a Navigator tree or a table-preview dialog. Navigator lists the source’s tables/items and previews the selected object; users can select one or more objects before continuing. Desktop Navigator has a limit of 10,000 listed objects (this is an object-list limit, not an imported-row limit); Microsoft documents a Transform Data workaround to filter the full navigation table. [Get Data preview and Navigator](https://learn.microsoft.com/en-us/power-query/get-data-experience)
8. **Choose Load or Transform Data.** **Load** adds selected objects to the Desktop model using the chosen connectivity mode. **Transform Data** opens Power Query Editor first. Connector and UI experience determine which buttons appear and where they are placed. [Connect to data in Power BI Desktop](https://learn.microsoft.com/en-us/power-bi/connect-data/desktop-quickstart-connect-to-data)
9. **Prepare and inspect the query.** Power Query Editor supports multiple queries, data preview, data profiling, and a sequence of saved Applied Steps. In the redesigned editor experience (currently documented as Preview), users also get Data, Schema, and Diagram views. Users can inspect, edit, rename, reorder, or delete steps; edit a step in the formula bar; or use Advanced Editor to write M. The functionality spans query filtering/cleanup, query-to-query merge and append, folder combination, custom calculations, and source-specific transformations. Power Query does not modify the original source file. Query folding can push supported steps to the source; support depends on connector and operation. [Power Query Editor overview](https://learn.microsoft.com/en-us/power-bi/transform-model/desktop-query-overview), [Applied Steps](https://learn.microsoft.com/en-us/power-query/applied-steps), [Power Query best practices and profiling](https://learn.microsoft.com/en-us/power-query/best-practices), [Query folding](https://learn.microsoft.com/en-us/power-query/query-folding-basics)
10. **Combine files or queries.** Folder connectors can list files in a folder/subfolders and combine them using an example file, then either load directly or open the result for transformation. Combine behavior expects matching file structures; users can filter the file list before combining. Power Query can also append or merge queries from separate sources. [Folder connector](https://learn.microsoft.com/en-us/power-query/connectors/folder), [Combine files in Desktop](https://learn.microsoft.com/en-us/power-bi/transform-model/desktop-combine-binaries)
11. **Apply and control query loading.** After transformations, **Close & Apply** runs the query steps and loads results into the PBIX model. Query properties include **Enable load** (include/exclude an intermediate query from the model) and **Include in report refresh** (exclude a query from refresh). [Query Editor overview](https://learn.microsoft.com/en-us/power-bi/transform-model/desktop-query-overview), [Managing query refresh](https://learn.microsoft.com/en-us/power-bi/connect-data/refresh-include-in-report-refresh)
12. **Save or reuse a connection.** PBIX saves the report/model work. Recent sources can reconnect. A PBIDS file can be exported/shared to preconfigure one data source; opening it prompts for credentials and then opens Navigator for object selection. [Power BI Desktop sources and PBIDS](https://learn.microsoft.com/en-us/power-bi/connect-data/desktop-data-sources)
13. **Refresh and diagnose.** Desktop refresh re-reads data/schema from its sources. After publishing an Import model, Power BI Service can run on-demand or scheduled refresh; settings cover source credentials, gateway mapping for sources that require one, schedule, and refresh history/errors. DirectQuery/live connection follow different refresh semantics. [Power BI refresh](https://learn.microsoft.com/en-us/power-bi/connect-data/refresh-data), [Scheduled refresh](https://learn.microsoft.com/en-us/power-bi/connect-data/refresh-scheduled-refresh)

### Other Desktop entry routes

- **Enter Data / Blank Table:** create a table by typing values or pasting data, then optionally open it in Power Query for editing before loading. [Enter data directly](https://learn.microsoft.com/en-us/power-bi/connect-data/desktop-enter-data-directly-into-desktop), [Blank Table in Get Data](https://learn.microsoft.com/en-us/power-bi/connect-data/desktop-data-sources)
- **Blank Query:** begin with an empty query and create its source or transformations with M in Power Query Editor. [Desktop Get Data experience](https://learn.microsoft.com/en-us/power-bi/connect-data/desktop-data-sources)
- **Import an Excel workbook model:** **File → Import → Power Query, Power Pivot, Power View** converts workbook Power Query queries/groups, Power Pivot external connections, linked/current workbook tables, and supported model objects such as calculated columns, measures, KPIs, data categories, and relationships into a Power BI Desktop file with a report based on the workbook. Some objects are skipped or have import limits, including hierarchies and binary columns. This is separate from Get Data → Excel for worksheet data. [Import Excel workbooks](https://learn.microsoft.com/en-us/power-bi/connect-data/desktop-import-excel-workbooks)
- **Template Apps:** the legacy Get Data dialog exposes an organization-dependent Template Apps entry. [Desktop Get Data experience](https://learn.microsoft.com/en-us/power-bi/connect-data/desktop-data-sources)

### Related web/online flow

Power Query Online is not the same UI as Desktop. It combines connection settings and credentials into a reusable named connection, with connector-specific gateway, authentication, privacy, and other settings; users can select and edit saved connections. It previews data and sends selected data into the Power Query Editor before the host saves it. Its modules can include Home, New, Recent, Dataflow templates (Power BI Service), OneLake catalog and New Fabric item (Fabric), Azure data sources, Upload file, Blank table, and Blank query. Upload file supports local browse or drag-and-drop for Excel, JSON, PDF, Text/CSV, and XML. Power BI Service scheduled-refresh settings are later semantic-model administration, separate from Desktop import. [Power Query Desktop vs. Online stages and modules](https://learn.microsoft.com/en-us/power-query/get-data-experience), [Online connections and authentication](https://learn.microsoft.com/en-us/power-query/connection-authentication-pqo), [Scheduled refresh](https://learn.microsoft.com/en-us/power-bi/connect-data/refresh-scheduled-refresh)

## 3. Main capability gaps against Power BI

- Real database, cloud, web, service, semantic-model, and OneLake connections, including connector-specific settings and authentication.
- Navigator-style selection of multiple objects/tables and multi-table model loading.
- SharePoint multi-file discovery; PDF import; Parquet type retention and directory/cloud sources.
- Power Query Editor compatibility: local append and six exact-match merge joins are implemented for loaded tables, with flat query groups. Nested groups, fuzzy joins, selectable expansion/aggregation, a broad transform library, M formula bar/Advanced Editor, and query folding remain unavailable.
- Import/DirectQuery/live/Direct Lake connection paths, plus query-level load and refresh properties.
- Credential management, privacy levels, source permissions, gateway configuration, scheduled refresh, and refresh history.
- Minimum M1 performance acceptance for the shared local-file preview remains pending.
