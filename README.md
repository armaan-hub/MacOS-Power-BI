# Analytics Studio

Native desktop analytics authoring application. The frontend uses PySide6 with Qt Quick/QML; Python owns project lifecycle and local CSV, Excel, JSON, XML, Parquet, Folder, and SQLite data behavior. The workspace provides Report, Data, and Model views, a tabbed ribbon, data preview, and versioned project open/save/recovery.

## Run from source

Use Python 3.10 or newer with an Apple Silicon build on macOS:

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m analytics_studio.main
```

Open an existing `.npa` project from **File → Open Project**, or pass its path as the first argument.

## Target platforms

- **First release:** Apple Silicon Macs (M1 or newer), macOS Sonoma 14.4 or later. The intended support and manual-check matrix is Sonoma 14.4, Sequoia 15, and Tahoe 26.
- **Later Linux target:** Ubuntu 24.04 LTS on x86_64.
- **Mac-like Linux desktop check:** elementary OS, as a user-experience check rather than a separate supported deployment target.

The current frontend uses PySide6 and Qt Quick/QML. Ribbon and pane glyphs use curated Fluent System Icons SVGs under their MIT license; see `analytics_studio/qml/icons/fluent/README.md`. App-authored SVGs supply file-format marks in the connector picker. The `.npa` format and core project code use Python's standard library.

## Current scope

Report, Data, and Model are native workspace views. The ribbon follows the supplied Power BI layout references with File, Home, Insert, Modeling, View, Optimize, and Help tabs. Switching to Report or Data selects Home; switching to Model selects Modeling. Data has a source-fields pane beside its 500-row preview, and Model shows table fields, measure values, calculated-column definitions, saved calculated-table and calendar expressions, and relationships. File New/Open/Save/Save As and active-table CSV export work locally. Home imports Text/CSV, Excel Workbook (`.xls`/`.xlsx`/`.xlsm`), JSON, XML, Parquet, local SQLite tables/views through preview-and-confirm workflows, SQL Server tables/views through an ODBC connection workflow, anonymous HTTPS OData v4 entity sets through a service-root workflow, and Web URLs serving CSV, JSON, XML, Excel, Parquet, or static HTML tables. Web uses anonymous HTTPS GET; credentials, cookies, custom headers, POST, pagination, and JavaScript-rendered pages are not supported, and the URL is stored in the project. Fresh Excel imports default to worksheet row 1 as column names; users can choose automatic detection or another one-based header row in the preview. Existing saved source options are retained. Local file imports are limited to 10 MiB per source, 100,000 rows, 512 columns, and 500,000 cells; `.xlsx`/`.xlsm` workbook contents are limited to 80 MiB uncompressed. These are defensive caps, not measured performance guarantees for the minimum supported Mac. Home also supports bounded Recent Sources, typed/pasted delimited data, deterministic sample data, active-source refresh, Refresh All for supported linked sources and included saved queries, and a local Transform Data workflow with editable and reorderable applied steps for column selection, rename/remove, exact value replacement, extracting text before or after a selected delimiter occurrence and text between two delimiters, splitting at the first delimiter, splitting at every delimiter into columns or rows, and splitting by positions, merge columns with a chosen separator, Fill Down/Fill Up on selected columns, Duplicate Column, Remove Blank Rows, Remove Top Rows, Remove Bottom Rows, Keep Top Rows, Keep Bottom Rows, Keep Range of Rows, Add Index Column, Reorder Columns, Use First Row as Headers, Use Headers as First Row, Transpose Table, multi-key Group By with multiple aggregations, unpivot selected/other columns, pivot with selectable aggregation, bounded safe M-style custom columns, ordered Conditional Column rules, text trimming, Clean Text control-character removal, and locale-neutral Lowercase, Uppercase, and Capitalize Each Word conversions plus Reverse Text on Text-typed fields before non-text conversion, duplicate removal and retention by selected columns, multi-column sorting with saved priority and an independent direction per key, text filters for contains/begins/ends and their negations, numeric filters for greater/less than including inclusive bounds, advanced multi-column AND/OR filters, Is blank/Is not blank row filters, row filtering/sorting, and text/whole-number/decimal/boolean/date/date-time/time conversion. Change Type Using Locale parses whole/decimal numbers and date/time values with a saved Babel/CLDR culture. Unpivot emits Attribute/Value pairs for non-empty cells and lets users name both output columns. Pivot turns distinct values into output columns and supports no-aggregate, count, min/max, median, sum, and average; repeated key/category pairs need an aggregate choice. Custom columns support field references, conditionals, operators, and selected Text, Number, and Date functions; outputs default to text and can be converted by a later step. Conditional Column supports ordered clauses with literal or column-based comparisons and outputs, plus a final Else. Merge Columns combines selected fields in display order with a configurable separator, removes those fields, and creates a text output. Fill Down and Fill Up propagate nearby non-empty values through blank cells in selected columns; leading Fill Down blanks and trailing Fill Up blanks remain empty when there is no value in that direction. Duplicate Column appends a copy of one field's values and preserves its type. Remove Blank Rows drops only rows whose cells are all empty; whitespace-only cells keep the row. Remove Top Rows removes a chosen number from the top of the table and preserves the remaining order. Remove Bottom Rows removes a chosen number from the end and preserves the preceding order. Keep Top Rows retains a chosen number from the start of the table and preserves their order. Keep Bottom Rows retains a chosen number from the end while preserving order. Keep Range of Rows retains a chosen contiguous slice using a one-based first row and a row count. Remove Alternate Rows starts at a one-based row, then repeatedly removes a chosen count and keeps a chosen count; rows above its starting position stay. Add Index Column appends a whole-number sequence with a configurable start and increment. Transpose Table turns rows into columns and columns into rows, drops original column names, and creates sequential Column1-style output names; use First Row as Headers as a separate step. Split Column at Every Delimiter into Columns and Extract Text Before/After Delimiter are previous increments. Extract Text Between Delimiters is a previous increment. Capitalize Each Word is a previous increment. Reverse Text is a previous increment. Remove Duplicates by Selected Columns is a previous increment. Keep Duplicates by Selected Columns is a previous increment. Sort Rows by Multiple Columns is a previous increment. Text Filter Operators is a previous increment. Inclusive Numeric Filter Operators is a previous increment. Advanced multi-column filters and blank/nonblank row filters have automated lifecycle coverage. SQLite import has local fixture-based lifecycle coverage. SQL Server has mocked lifecycle coverage; live-server acceptance requires an installed driver and a server endpoint. OData and Web have mocked lifecycle coverage; acceptance against live endpoints remains pending. The Data view saves selected column types, validates normalized values, profiles valid/error/empty counts, distinct/unique values, and common values across all rows, and can save append and merge queries from available tables, assign entries to flat query groups, and turn Enable Load or Include in Report Refresh on or off for saved queries. A query excluded from model tables continues to evaluate for downstream queries; an excluded query keeps its last in-memory result during explicit refresh. Project open reevaluates saved query definitions because the file stores definitions rather than query result caches. Append requires identical ordered columns; merge supports paired key columns and six join kinds. Query definitions, load/refresh settings, and dependencies persist by source ID and rebuild on open or refresh. Transform steps replay after query evaluation. Inline tables are embedded and have no independent source to refresh. Saved-query lifecycle tests cover append/merge, dependencies, load settings, refresh settings, and replay; full M semantics remain outside scope. Local SQLite, SQL Server, OData Feed, and Web connectors are implemented in code. Power BI semantic models, OneLake catalog, Dataverse, and the remaining remote connectors remain unavailable. See [the source catalog notes](docs/data-source-catalog.md) for supported formats and unavailable entries. Report summaries infer common sales, amount, date, geography, cost, and quantity columns and display an explanatory message when a chart field is missing. Modeling supports creating, editing, and deleting relationships with cardinality, filter direction, active state, endpoint/type checks, and one-side key uniqueness validation; active relationships propagate supported current Region selections and saved report/page/visual filters into measures and active-table report summaries. The Filters pane supports saved page- and visual-scoped conditions for built-in KPI and revenue chart visuals: text matching, blank checks, numeric/date/time comparisons, multi-value inclusion/exclusion, relative-date rules on Date fields and relative-time rules on Date/time fields, and two conditions joined with AND/OR. Top N for the Region revenue visual and report-level filters across pages passed save/reopen lifecycle acceptance. Supported chart wells bind loaded fields; Y-axis Sum, Count, and Average settings persist. Chart and slicer selections support per-target Filter, Highlight, or None behavior. Visuals support editable text boxes, local images, vector shapes, saved title and placement, primary color, data labels, single-series legends, copy/cut/paste, z-order, multi-selection grouping and movement, report themes, one-shot Format Painter, and button URL actions. The Build gallery creates blank bar, column, line, area, stacked bar/column/area, 100% stacked bar/column/area, pie, donut, funnel, waterfall, ribbon, treemap, matrix, table, card, and slicer visuals; Stacked charts group values by Legend and accept category selection and highlighting, while 100% variants normalize each category; Area charts render in category order, Pie/Donut charts support category selection, labels, legends, and cross-highlighting, and Table visuals display selected fields with row selection and highlighting. Card visuals display built-in KPI values or a selected field with Sum, Count, or Average, and accept linked filtering/highlights. Funnel charts render value-scaled categories and support click filtering. Waterfall charts render positive and negative changes against running totals and support category filtering. Ribbon charts rank Legend categories within each X-axis period and connect ranks across periods. Treemaps size category tiles by value and support category filtering. Matrix visuals pivot a row group against a column group with Sum, Count, or Average cells and row filtering. The local DAX evaluator implements a bounded set of scalar and table-filter forms, including aggregates and iterators, selected `CALCULATE` filters and modifiers (`FILTER`, `KEEPFILTERS`, `REMOVEFILTERS`, `ALL`, `ALLEXCEPT`, `ALLSELECTED`), limited context transition, selected relationship modifiers, and date calculations. The supported forms and semantic boundaries are listed in the [DAX compatibility contract](DAX_COMPATIBILITY_CONTRACT.md); parser recognition does not establish full Power BI DAX or Tabular behavior. One table is active at a time. `.npa` version 78 stores active-source metadata, inline rows, per-column types, transform steps, measure and calculated-column definitions, relationship definitions, append/merge/calculated-table/calendar query definitions, query groups, query load/refresh settings, query functions, and dependencies; versions 1–77 migrate in memory and upgrade to v78 on explicit save. New reports start empty, and untouched version-73 starter visuals are removed during migration. The app also lacks full filter-path analysis, broad cross-table DAX, sharing, advanced report-object editing, additional connector implementations, and most other visual types. The independent shell follows the reference layout but does not provide whole-product parity.


SQL Server import uses Microsoft ODBC Driver 17 or 18 with SQL username/password authentication and TLS certificate validation. It lists tables and views, previews up to 100 rows, then imports the selected object locally with row, column, cell, per-cell text, and total text limits. Passwords are kept in macOS Keychain; the project stores connection/object settings and an opaque Keychain reference, and refresh rereads the selected object. Install the ODBC driver separately using [Microsoft's macOS guide](https://learn.microsoft.com/en-us/sql/connect/odbc/linux-mac/install-microsoft-odbc-driver-sql-server-macos?view=sql-server-2017). Runtime acceptance with a live SQL Server and Apple Silicon driver remains pending. Windows/Entra authentication, generic ODBC, DirectQuery, query folding, and gateway or Service refresh are not implemented; SQL Server sources also do not appear in local Recent Sources.

The QML shell is rendered in offscreen Qt across Report, Data, and Model, including the 1040×680 minimum layout. See the [empty-project capture](docs/screenshots/powerbi-guided-home-empty-project.png), [Insert ribbon](docs/screenshots/powerbi-guided-insert.png), [CSV-loaded report](docs/screenshots/powerbi-guided-csv-loaded.png), [Data view](docs/screenshots/powerbi-guided-data.png), and [Model view](docs/screenshots/powerbi-guided-modeling.png).

The local multi-table workflow keeps each supported import as its own project table. Folder combine filters CSV, Excel, JSON, or XML files by type and filename, can include subfolders, uses a selected sample file for parser settings, checks matching column schemas, and can add a `Source.Name` column (enabled by default). Folder selections are limited to 500 files and 100 MiB of matching source data, with a 10 MiB per-file limit. Use the Data view selector to switch the active table; refreshing a linked table reloads that source, while refreshing a saved append query reloads its dependency chain and rebuilds downstream queries. Re-importing the same linked source updates its existing table, and Remove table removes the project entry without deleting linked files or folder contents. Built-in report totals/charts still evaluate the selected table only; active relationship paths apply to supported qualified measures. Automated lifecycle tests cover Folder combine, Parquet import/refresh, `.xls` parsing, SQLite table/view import/refresh, and saved append queries. These fixture tests do not replace live SQL Server/OData/Web acceptance or native macOS UI review. Parquet imports one local flat-scalar file through PyArrow; values become text, nulls become blank, and types are not retained. It is limited to 10 MiB input, 80 MiB row-group uncompressed data, and 80 MiB rendered text. SQLite imports one local table or view per project table from a read-only `.db`, `.sqlite`, or `.sqlite3` file; it preserves the object selection for reopen and refresh, converts scalar values to text, and rejects BLOB values. SQLite input, including an optional write-ahead log, is limited to 10 MiB; each query has a roughly 10-second work deadline, and rendered output is limited to 80 MiB.

## DAX and Power Query

To author DAX, load a table and choose **New DAX measure** on the Home or Modeling ribbon, or in Model view. The editor provides searchable templates for the recognized DAX function and constant forms; supported evaluation forms and limitations are listed in the DAX compatibility contract. To edit queries, choose **Transform data** on Data Home to open the separate six-tab **Power Query Editor**, then choose **Advanced Editor (M)** on its Home or View ribbon. The M editor parses and previews a documented local subset of Power Query M and applies supported queries as saved transformation steps. Neither editor provides the complete Microsoft DAX or Power Query M language/runtime; unsupported expressions are reported instead of executed.
