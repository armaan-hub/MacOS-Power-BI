# Analytics Studio

Native desktop analytics authoring application. The frontend uses PySide6 with Qt Quick/QML; Python owns project lifecycle and local CSV, Excel, JSON, XML, Parquet, Folder, and SQLite data behavior. The workspace provides Report, Data, and Model views, a tabbed ribbon, data preview, and versioned project open/save/recovery.

## Run from source

Use Python 3.10 or newer with an Apple Silicon build on macOS:

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m analytics_studio.main
```

Open an existing `.npa` project from **File → Open Project**, or pass its path as the first argument.

## Target platforms

- **First release:** Apple Silicon Macs (M1 or newer), macOS Sonoma 14.4 or later. The intended support and manual-check matrix is Sonoma 14.4, Sequoia 15, and Tahoe 26.
- **Later Linux target:** Ubuntu 24.04 LTS on x86_64.
- **Mac-like Linux desktop check:** elementary OS, as a user-experience check rather than a separate supported deployment target.

The current frontend uses PySide6 and Qt Quick/QML. Ribbon and pane glyphs use curated Fluent System Icons SVGs under their MIT license; see `analytics_studio/qml/icons/fluent/README.md`. App-authored SVGs supply file-format marks in the connector picker. The `.npa` format and core project code use Python's standard library.

## Current scope

Report, Data, and Model are native workspace views. The ribbon follows the supplied Power BI layout references with File, Home, Insert, Modeling, View, Optimize, and Help tabs. Switching to Report or Data selects Home; switching to Model selects Modeling. Data has a source-fields pane beside its 500-row preview, and Model shows table fields, measure values, calculated-column definitions, saved calculated-table and calendar expressions, and relationships. File New/Open/Save/Save As and active-table CSV export work locally. Home imports Text/CSV, Excel Workbook (`.xls`/`.xlsx`/`.xlsm`), JSON, XML, Parquet, local SQLite tables/views through preview-and-confirm workflows, SQL Server tables/views through an ODBC connection workflow, anonymous HTTPS OData v4 entity sets through a service-root workflow, and Web URLs serving CSV, JSON, XML, Excel, Parquet, or static HTML tables. Web uses anonymous HTTPS GET; credentials, cookies, custom headers, POST, pagination, and JavaScript-rendered pages are not supported, and the URL is stored in the project. Excel preview recommends a tabular worksheet and detects a likely header row beneath title blocks; users can still choose the worksheet and header row manually. Local file imports are limited to 10 MiB per source, 100,000 rows, 512 columns, and 500,000 cells; `.xlsx`/`.xlsm` workbook contents are limited to 80 MiB uncompressed. These are defensive caps, not measured performance guarantees for the minimum supported Mac. Home also supports bounded Recent Sources, typed/pasted delimited data, deterministic sample data, active-source refresh, Refresh All for supported linked sources and included saved queries, and a local Transform Data workflow with editable and reorderable applied steps for column selection, rename/remove, exact value replacement, extracting text before or after a selected delimiter occurrence and text between two delimiters, splitting at the first delimiter, splitting at every delimiter into columns or rows, and splitting by positions, merge columns with a chosen separator, Fill Down/Fill Up on selected columns, Duplicate Column, Remove Blank Rows, Remove Top Rows, Remove Bottom Rows, Keep Top Rows, Keep Bottom Rows, Keep Range of Rows, Add Index Column, Reorder Columns, Use First Row as Headers, Use Headers as First Row, Transpose Table, multi-key Group By with multiple aggregations, unpivot selected/other columns, pivot with selectable aggregation, bounded safe M-style custom columns, ordered Conditional Column rules, text trimming, Clean Text control-character removal, and locale-neutral Lowercase, Uppercase, and Capitalize Each Word conversions plus Reverse Text on Text-typed fields before non-text conversion, duplicate removal and retention by selected columns, multi-column sorting with saved priority and an independent direction per key, text filters for contains/begins/ends and their negations, numeric filters for greater/less than including inclusive bounds, advanced multi-column AND/OR filters, Is blank/Is not blank row filters, row filtering/sorting, and text/whole-number/decimal/boolean/date/date-time/time conversion. Change Type Using Locale parses whole/decimal numbers and date/time values with a saved Babel/CLDR culture. Unpivot emits Attribute/Value pairs for non-empty cells and lets users name both output columns. Pivot turns distinct values into output columns and supports no-aggregate, count, min/max, median, sum, and average; repeated key/category pairs need an aggregate choice. Custom columns support field references, conditionals, operators, and selected Text, Number, and Date functions; outputs default to text and can be converted by a later step. Conditional Column supports ordered clauses with literal or column-based comparisons and outputs, plus a final Else. Merge Columns combines selected fields in display order with a configurable separator, removes those fields, and creates a text output. Fill Down and Fill Up propagate nearby non-empty values through blank cells in selected columns; leading Fill Down blanks and trailing Fill Up blanks remain empty when there is no value in that direction. Duplicate Column appends a copy of one field's values and preserves its type. Remove Blank Rows drops only rows whose cells are all empty; whitespace-only cells keep the row. Remove Top Rows removes a chosen number from the top of the table and preserves the remaining order. Remove Bottom Rows removes a chosen number from the end and preserves the preceding order. Keep Top Rows retains a chosen number from the start of the table and preserves their order. Keep Bottom Rows retains a chosen number from the end while preserving order. Keep Range of Rows retains a chosen contiguous slice using a one-based first row and a row count. Remove Alternate Rows starts at a one-based row, then repeatedly removes a chosen count and keeps a chosen count; rows above its starting position stay. Add Index Column appends a whole-number sequence with a configurable start and increment. Transpose Table turns rows into columns and columns into rows, drops original column names, and creates sequential Column1-style output names; use First Row as Headers as a separate step. Split Column at Every Delimiter into Columns and Extract Text Before/After Delimiter are previous increments. Extract Text Between Delimiters is a previous increment. Capitalize Each Word is a previous increment. Reverse Text is a previous increment. Remove Duplicates by Selected Columns is a previous increment. Keep Duplicates by Selected Columns is a previous increment. Sort Rows by Multiple Columns is a previous increment. Text Filter Operators is a previous increment. Inclusive Numeric Filter Operators is a previous increment. Advanced multi-column filters are a previous increment; runtime acceptance is pending. Blank and nonblank row filters are a previous increment; runtime acceptance is pending. SQLite database and SQL Server import are previous increments; anonymous HTTPS OData Feed and bounded Web import are implemented in code; live runtime acceptance is pending. The Data view saves selected column types, validates normalized values, profiles valid/error/empty counts, distinct/unique values, and common values across all rows, and can save append and merge queries from available tables, assign entries to flat query groups, and turn Enable Load or Include in Report Refresh on or off for saved queries. A query excluded from model tables continues to evaluate for downstream queries; an excluded query keeps its last in-memory result during explicit refresh. Project open reevaluates saved query definitions because the file stores definitions rather than query result caches. Append requires identical ordered columns; merge supports paired key columns and six join kinds. Query definitions, load/refresh settings, and dependencies persist by source ID and rebuild on open or refresh. Transform steps replay after query evaluation. Inline tables are embedded and have no independent source to refresh. Saved-query runtime acceptance is pending. Local SQLite, SQL Server, OData Feed, and Web connectors are implemented in code. Power BI semantic models, OneLake catalog, Dataverse, and the remaining remote connectors remain unavailable. See [the source catalog notes](docs/data-source-catalog.md) for supported formats and unavailable entries. Report summaries infer common sales, amount, date, geography, cost, and quantity columns and display an explanatory message when a chart field is missing. Modeling supports creating, editing, and deleting relationships with cardinality, filter direction, active state, endpoint/type checks, and one-side key uniqueness validation; active relationships propagate supported current Region selections and saved report/page/visual filters into measures and active-table report summaries. The Filters pane supports saved page- and visual-scoped conditions for built-in KPI and revenue chart visuals: text matching, blank checks, numeric/date/time comparisons, multi-value inclusion/exclusion, relative-date rules on Date fields and relative-time rules on Date/time fields, and two conditions joined with AND/OR. Top N for the Region revenue visual and report-level filters across pages passed save/reopen lifecycle acceptance. Local measures use a safe DAX subset: `SUM`, `AVERAGE`, `MIN`, `MAX`, `COUNT`, `COUNTA`, `DISTINCTCOUNT`, `COUNTROWS`, `DIVIDE`, `ABS`, `ROUND`, `IF`, `AND`, `OR`, `NOT`, `SUMX`, `AVERAGEX`, arithmetic, measure references, and `CALCULATE(expression)`. Boolean `CALCULATE` filters support typed single-column comparisons, AND/OR/NOT composition, multiple ANDed arguments, same-column filter replacement, and `KEEPFILTERS` intersection; ordinary comparisons coerce `BLANK()` to zero, false, empty text, or 1899-12-30 by column type. Text equality is case-sensitive and date/time literals use ISO syntax. Nested Boolean and time-intelligence calculations preserve the outer date set when filter provenance is available; those filters cannot yet appear together in one `CALCULATE` call. Marked-date `CALCULATE` filter forms support `DATEADD`, `SAMEPERIODLASTYEAR`, `DATESYTD`, `DATESQTD`, `DATESMTD`, `DATESBETWEEN`, `DATESINPERIOD`, `PREVIOUSYEAR`, `PREVIOUSQUARTER`, and `PREVIOUSMONTH`; `TOTALYTD` supports calendar years and ASCII M/D fiscal year ends, while `TOTALQTD` and `TOTALMTD` support calendar periods. Table-valued filters, other filter modifiers, context transition, same-call Boolean/time-intelligence filter combinations, and broader DAX remain unsupported. Calculated columns support same-table numeric/boolean row expressions with arithmetic, comparisons, `IF`, `AND`, `OR`, `NOT`, `ABS`, and `ROUND`; calculated tables support `DISTINCT('Table'[Column])` with preview and refresh replay. Formula definitions persist and recompute when data changes. Qualified aggregate references can read loaded related tables through active relationships; this remains a bounded DAX subset. One table is active at a time. `.npa` version 66 stores active-source metadata, inline rows, per-column types, transform steps, measure and calculated-column definitions, relationship definitions, append/merge/calculated-table/calendar query definitions, query groups, query load/refresh settings, and dependencies; versions 1–65 migrate in memory and upgrade to v66 on explicit save. The app also lacks full filter-path analysis, broad cross-table DAX, sharing, advanced report-object editing, additional connector implementations, and most other visual types. The independent shell follows the reference layout but does not provide whole-product parity.


SQL Server import uses Microsoft ODBC Driver 17 or 18 with SQL username/password authentication and TLS certificate validation. It lists tables and views, previews up to 100 rows, then imports the selected object locally with row, column, cell, per-cell text, and total text limits. Passwords are kept in macOS Keychain; the project stores connection/object settings and an opaque Keychain reference, and refresh rereads the selected object. Install the ODBC driver separately using [Microsoft's macOS guide](https://learn.microsoft.com/en-us/sql/connect/odbc/linux-mac/install-microsoft-odbc-driver-sql-server-macos?view=sql-server-2017). Runtime acceptance with a live SQL Server and Apple Silicon driver remains pending. Windows/Entra authentication, generic ODBC, DirectQuery, query folding, and gateway or Service refresh are not implemented; SQL Server sources also do not appear in local Recent Sources.

The QML shell is rendered in offscreen Qt across Report, Data, and Model, including the 1040×680 minimum layout. See the [empty-project capture](docs/screenshots/powerbi-guided-home-empty-project.png), [Insert ribbon](docs/screenshots/powerbi-guided-insert.png), [CSV-loaded report](docs/screenshots/powerbi-guided-csv-loaded.png), [Data view](docs/screenshots/powerbi-guided-data.png), and [Model view](docs/screenshots/powerbi-guided-modeling.png).

The local multi-table workflow keeps each supported import as its own project table. Folder combine filters CSV, Excel, JSON, or XML files by type and filename, can include subfolders, uses a selected sample file for parser settings, checks matching column schemas, and can add a `Source.Name` column (enabled by default). Folder selections are limited to 500 files and 100 MiB of matching source data, with a 10 MiB per-file limit. Use the Data view selector to switch the active table; refreshing a linked table reloads that source, while refreshing a saved append query reloads its dependency chain and rebuilds downstream queries. Re-importing the same linked source updates its existing table, and Remove table removes the project entry without deleting linked files or folder contents. Built-in report totals/charts still evaluate the selected table only; active relationship paths apply to supported qualified measures. Runtime acceptance for Folder save/reopen, schema errors, independent refresh, Parquet type/limit behavior, `.xls` date/formula behavior, SQLite table/view selection and refresh, and saved append queries is pending. Parquet imports one local flat-scalar file through PyArrow; values become text, nulls become blank, and types are not retained. It is limited to 10 MiB input, 80 MiB row-group uncompressed data, and 80 MiB rendered text. SQLite imports one local table or view per project table from a read-only `.db`, `.sqlite`, or `.sqlite3` file; it preserves the object selection for reopen and refresh, converts scalar values to text, and rejects BLOB values. SQLite input, including an optional write-ahead log, is limited to 10 MiB; each query has a roughly 10-second work deadline, and rendered output is limited to 80 MiB.

The ribbon uses the supplied Power BI references for command density and group order. Report Home shows Clipboard, Data, Queries, Insert, Calculations, Sensitivity, and Share groups. The Insert tab uses Pages, Visuals, AI visuals, Elements, and Sparklines groups. Ribbon labels wrap fully within their controls. Home supports local data import, enter/paste/sample data, recent-source re-import, transform, linked-file refresh, CSV export, page creation, and the included revenue charts. Commands without local implementations are disabled; cloud publishing and sensitivity labels remain unavailable. More visuals, Buttons/Navigator, and Shapes are unavailable until their report-object workflows are implemented. Data Home retains Excel workbook, OneLake catalog, SQL Server, Enter data, Dataverse, Recent sources, Transform data, and Refresh commands; service connectors are unavailable. Modeling starts with Data & model navigation, then Relationships, Calculations, Calendars, Page refresh, Parameters, Security, and Q&A. View and Optimize expose their pane, page, and analysis groups. The existing automated suite covers project actions and the baseline CSV, Excel, JSON, and XML import flows; Folder, Parquet, `.xls`, SQLite, and SQL Server runtime acceptance is pending.

The Visualizations pane draws each chart glyph from the local vector icon set, aligned with its own selectable tile. Bar, Column, and Line are active; unsupported visual types are disabled. The pane includes Build, Format, and Analytics tabs plus Values and Drill through wells. In Report, Filters and Data remain narrow rails by default, and the Visualizations pane stays open. The Data workspace has a separate fields pane. Active actions use blue, teal, and amber accents.

The screenshots are offscreen Qt renders, so the native macOS title bar and system menu placement are not represented. The interface is an independent, screenshot-guided shell, not a pixel-identical Power BI clone or a claim of whole-product parity.
