# Task 172 — dax-hunt-172: EARLIER/EARLIEST without enough outer row contexts is refused at compile time, as in Power BI

Goal: the t225 fresh batch (1994 random rows over 14 function groups) left 14 wrong. 13 are known last-digit limits. The other one: Power BI refuses the whole query when EARLIER or EARLIEST has fewer outer row contexts than it needs. It does this at compile time, so the error also appears:
- in a branch that never runs, e.g. `IF(FALSE(),EARLIER(Facts[Sales]),1)`;
- over an empty table, e.g. `MINX(TOPN(0,Facts,Facts[Sales]),EARLIER(Facts[Sales]))`;
- inside IFERROR or ISERROR, which do not catch it.

The app evaluated these lazily and answered 1 or "E".

Spec: t225 (1994 random rows), plus t226 (20 EARLIER variants), all measured in Power BI Desktop on the iPad guest. None of it is read by the app.
