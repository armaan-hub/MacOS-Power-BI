# Task 144 — dax-hunt-144: wrong DAX answers from the hunt backlog (batch 2)

Goal: remove the wrong answers in the hunt backlog families, checked against Power BI Desktop in the guest. Refusing is
always better than guessing.

Spec: 477 measured expressions (14 invalid `--` probes dropped), split into `spec` (347) and a hidden `holdout` (116),
plus 16 extra Power BI answers measured during review (FLOOR/CEILING residues, STDEVX/VARX shapes). None is read by the app.

Families (Haiku 5.5 coded, Sonnet 5.5 reviewed and tested, Haiku applied the review fixes):
- J. Query-level errors IFERROR cannot catch: PERCENTILE.EXC/INC with an invalid k over a column, SAMPLE with a negative
  count, CALENDAR with end before start or an invalid date, XIRR with a text date that cannot convert.
- K. FLOOR/CEILING (and ODD/EVEN of them) with a fractional significance in binary double: x/s rounded to 15 significant
  digits half up, then floor/ceil, times s; the exact Decimal is kept when it equals that double. Power BI measured
  CEILING(0.3,0.1)-0.3 = 5.55E-17, so the old FLOOR/CEILING tests now compare at 15 digits (values unchanged).
- L. EFFECT carried as a double; PRICEDISC computed left to right in double (basis 0 and 1 differ in the last digit).
- M. VARX/STDEVX return the one-pass double result where its 15-digit value differs from the Decimal one.
- N. ISPMT with a CURRENCY principal returns CURRENCY (4 decimals).
- H. ODDFYIELD with a long first coupon refuses.
- O. PRODUCTX over row-dependent CURRENCY: Power BI uses a log-based product that could not be reproduced; refusing
  broke 50 locked answers, so the main behaviour is kept (15th-digit differences, accepted by the gate) and the case is in
  the hunt backlog.

## Results
Scorer: spec 326 exact, 19 refused, 2 wrong (the two PRODUCTX/CURRENCY 15th-digit rows, unchanged from main); holdout
108 exact, 8 refused, 0 wrong before the PRODUCTX refusal was removed; Task 143 sets still 0 wrong.
