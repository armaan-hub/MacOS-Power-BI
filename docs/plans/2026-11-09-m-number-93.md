## Key points
- The number model is in `values.py` (Decimal-text literals vs Double; .NET "R" text). Typed results matter: e.g.
  `Number.Round(2.5)` prints `2.0` in Power BI (a Decimal-typed result?) while `Number.Round(3)` may print `3` — read
  the spec carefully and model the result representation of each function so the canonical text is exact
  (Int64.From / Decimal.From / Currency.From etc. results may print differently from Double results).
- Banker's rounding by default (`RoundingMode.ToEven`) for Number.Round; the other modes per name.
- `Number.ToText` / `Number.FromText` / `X.From(text)` use .NET format strings and en-US culture; other cultures in
  the spec (de-DE) must match; any culture or format not covered must be an explicit ERR, never a guess.
- Overflow / range errors use Power BI's exact messages from the spec.
- `Number.Random`, `Number.RandomBetween` are random (only type/range checked).
