## Signature and meaning
`XNPV(<Table>, <Values>, <Dates>, <Rate>)` : exactly 4 arguments. `<Values>`, `<Dates>` are expressions evaluated once per row of `<Table>` (row context). `<Rate>` is a scalar evaluated once, outside the row context.
Result = sum over the table rows of `value / (1 + Rate) ^ ((date - earliestDate) / 365)`, as a double.

## Rules (all taken from the saved answers; read the exact expressions and results from the JSON, do not retype)
1. **Base date is the earliest date in the table**, not the first row. Row order does not matter (`{100@365, -1000@0, 300@730}` at 10% is `-661.157024793388`).
2. **Dates are whole days.** A fractional part is ignored (`[d]+0.5` gives the same answer as `[d]`). A numeric date column and a Date value both work. Shifting all dates by the same amount does not change the result.
3. **Rate**: `0` gives the plain sum. A BLANK rate counts as 0. A text rate that reads as a number (`"0.1"`) works. `TRUE()` counts as 1. A rate of `-1` or lower is an error (refuse). A text rate that is not a number is an error (refuse). The rate may be any scalar expression (`0.1+0.05`, `1/3`, `SUM(...)/100`) but NOT a bare column reference of the table (Power BI error "A single value for column ... cannot be determined": refuse).
4. **Values**: a BLANK value makes that row ignored (the other rows keep their dates; the base date is still the earliest date among the rows that have a date). A string, Boolean or date value expression is an error (refuse: `XNPV(Facts,Facts[Region],...)`).
5. **Dates**: a BLANK date is an error (refuse). A text date is an error (refuse). `TRUE()` as the date expression is accepted by Power BI (every row has date 1, so there is no discounting: result is the plain sum). A date before 1900 or the year 9999 is accepted.
6. **Empty table** (after a FILTER) gives BLANK. A single row gives that row's value. Two rows on the same earliest date are not discounted.
7. **Table argument** may be a model table (`Facts`), `VALUES(col)`, `ALL(Facts)`, `FILTER`, `TOPN`, `CALCULATETABLE`, `ADDCOLUMNS(DATATABLE(...))`. Use the table expressions the engine already supports; if one is not supported today, it stays refused (do not add table functions in this task).
8. **Under a filter context** `CALCULATE(XNPV(Facts,...),Facts[Region]="East")` filters the table first (answer `7.99425807148921`).
9. **Aggregates inside the row expressions** are evaluated in the filter context, not per row (`XNPV(Facts,SUM(Facts[Quantity]),...)` is `89.9412752659951`: SUM is 15 on every row).
10. **Argument count**: fewer than 4 or more than 4 arguments is an error (refuse). A non-table first argument is an error (refuse).
11. **Floating point.** Power BI computes in double precision, so a result that is mathematically 0 can come out as `-1.4210854715202E-14`. The gate accepts a difference up to `1e-9` times `max(1, |result|)`, so use `float` (not `Decimal`) arithmetic and a `**` power per row; keep the sum in row order of the table.
