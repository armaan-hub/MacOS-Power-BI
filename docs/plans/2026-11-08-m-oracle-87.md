## Deliverable: `tools/m_oracle_diff.py`
- `power_query(expressions: list[str], port_: str, chunk: int = 100) -> list[str]` — Power BI's answer for each M expression.
  Mechanism (proved working on 2026-11-08 by Opus): create a scratch import table with an M partition through TMSL on
  the guest's Analysis Services port (`createOrReplace`), `refresh` it (`type: full`), read it with `EVALUATE`, then
  `delete` it — every time, also on failure (try/finally in the PowerShell). Reuse `tools.dax_oracle_diff`'s `guest`,
  `port`, `PS_HEAD` (import them; do not copy). The scratch table name is `MOracle__`; it is never saved.
- The partition's M is one `Table.FromRecords` over the batch: for expression *i* a record `[I = i, A = <answer text>]`, where
  the answer text is computed in M as
  `try Text.FromBinary(Json.FromValue(<expr>)) otherwise ...` — specify exactly: on success
  `"V:" & Text.From(Value.Type-name) & ":" & Text.FromBinary(Json.FromValue(v))` is not possible for every type, so use
  `let r = try (<expr>) in if r[HasError] then "ERR:" & r[Error][Reason] & ": " & r[Error][Message] else (try "V:" & Text.FromBinary(Json.FromValue(r[Value])) otherwise "V?:" & Text.From(r[Value]))`
  (a value Json cannot encode and Text.From cannot convert yields a third `try` → `"UNREPRESENTABLE"`). Expressions are
  pasted verbatim inside parentheses; each expression is independent.
- Answers are read back as base64 like `dax_oracle_diff.power_bi` does, and the count must equal the input count (retry up to 3×).
- A CLI: `PYTHONPATH=. python3 tools/m_oracle_diff.py in.json out.json` (list of expressions → list of answers).
