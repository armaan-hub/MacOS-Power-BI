# Task 188: Date Filters — Before, After, Between, Is Earliest, Is Latest

Planned by Claude Opus 5.5 (Team-Planner). Coded by Antigravity; two follow-ups by Haiku 5.5. Reviewed and tested by Sonnet 5.5 (Team-Thinker) over three rounds.

- New filter_rows operators: date_before, date_after, date_on_or_after, date_on_or_before (Between), is_earliest and is_latest.
  - Values are compared as parsed date or datetime values, never as strings. Null, empty and unparseable values never match.
  - Is Earliest and Is Latest keep tied rows; an all-null column gives no rows.
  - Non-date values are refused, and so are columns whose known type is text.
- The M uses the Power BI shapes:
  - `each [D] < #date(y, m, d)`
  - `each [D] >= #date(a) and [D] <= #date(b)`
  - `let earliest = List.Min(#"Prev"[D]) in Table.SelectRows(#"Prev", each [D] = earliest)`
  - `#datetime(y, m, d, 0, 0, 0)` for datetime columns
- Each shape round-trips through the Advanced Editor. Generic operators and their M are identical to main. `[D] = #date(...)` stays unsupported, as on main.
- Menu: five items are enabled. In the Next, In the Previous, Year, Quarter, Month, Week and Day stay disabled because they depend on today's date.
- Planner-authorised test edit: tests/test_power_query_column_menu_lifecycle.py, where the date-menu assertion now expects the five items enabled.
- Open item: the M shapes above came from the Planner's knowledge. Checking them on Power BI Desktop (guest VM) is on the parked VM-check list.
