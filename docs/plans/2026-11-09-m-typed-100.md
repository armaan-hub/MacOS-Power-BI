# Task 110 (Iteration 199): custom columns see typed cells, as after Power BI's Changed Type step (m-typed-100)

In Power BI the auto "Changed Type" step comes before user steps, so a custom-column formula sees numbers, dates and
logicals. Analytics Studio keeps query rows as imported text while steps run, infers `column_types`
(`transformations.infer_column_types`, `column_types_after_steps`) and applies them in the model afterwards. Task 109
worked around this in `_add_custom_column` (M error on a text cell -> fall back to the old evaluator), which still
lets silent differences through (`[Units] = 2` on text "2").

## Change
- The M path of `_add_custom_column` receives the column types in effect at that step (the inferred types of the
  source followed through the earlier steps — reuse `column_types_after_steps`; thread the map through
  `apply_transformations` without changing behaviour for other steps) and converts each referenced cell to that type
  with the app's existing typed-value conversion (the same rules the model uses when it applies `column_types`) before
  `cell_to_m`. A cell that fails conversion becomes the M error Power BI's Changed Type would produce, or the step
  refuses if that error is not measured.
- Remove the Task 109 text-cell fallback once typed cells are passed (old evaluator stays only where M refuses).
- Keep existing tests passing. If an existing assertion encodes the old text-cell behaviour, the new value must be
  the Power BI answer from this spec (or a live Power BI measurement); list every such change.

**Spec:** `docs/plans/2026-11-09-m-typed-100-spec.json` — 26 formulas x 4 rows measured on live Power BI:
`raw` is a text table as an import gives it, `types` is Power BI's Changed Type step, `cells[i]` the answer on row i.
Opus keeps 4 more formulas held out.

## Tests (`tests/test_m_typed_custom_column.py`, new)
- Build the candidate from `raw` text rows with the column types `types` (text, whole number, decimal number, date,
  true/false in the app's type names), run the custom column through `apply_transformations`, and require each cell
  to be exact or the step refused; wrong must be 0; minimum exact count.
- One real-app check (StudioController offscreen): import a small CSV with numeric/date text, add `[Units] = 2` and
  `Date.Year([Day])`, check the values.
