# Task 109 (Iteration 198): wire the M engine into custom columns (m-wire-99)

First wiring step for the M engine (`analytics_studio/m_engine/`, exact-or-refuse against Power BI). Today
`transformations._add_custom_column` evaluates formulas with the small evaluator in `power_query_expression.py`
(`compile_expression` / `evaluate_expression`). Keep that path exactly as it is for every formula it accepts (its
behaviour is locked by existing tests). When `compile_expression` rejects a formula (`PowerQueryExpressionError`),
evaluate it with the M engine instead.

**Spec:** `docs/plans/2026-11-09-m-wire-99-spec.json` — 48 formulas measured on live Power BI over a fixed 4-row
table (`table`): `cells[i]` is Power BI's `(each formula)(table{i})` (canonical `evaluate_to_text` form), and
`table_result` is `Table.AddColumn(table, "C", each formula)`. Opus keeps 12 more formulas held out.

## Interfaces
- New `analytics_studio/m_custom_column.py`:
  - `cell_to_m(value) -> MValue` — app cell (None, bool, Decimal/int/float, str, date, datetime, time,
    `PowerQueryCellError`) to an M value (a cell error becomes an M error raised when used).
  - `m_to_cell(value) -> Any` — M null/logical/number/text/date/datetime/time to the app's cell representation (use
    the same Python types the app's typed columns use; numbers must keep exact digits). Any other M kind (list,
    record, table, function, type, binary, duration, datetimezone) raises `MFormulaRefused`.
  - `compile_m_formula(expression: str) -> object` — parse `each <expression>` with the M parser; a syntax error
    raises `PowerQueryExpressionError` with the parser's message.
  - `evaluate_m_formula(compiled, row: dict) -> Any` — evaluates against the row as the record `_` (field access
    `[Col]`); returns `m_to_cell(result)`; a genuine M error returns a `PowerQueryCellError` with Power BI's reason and
    message; an engine refusal raises `MFormulaRefused`.
  - `class MFormulaRefused(Exception)`.
- Engine refusal = the engine's own "... is not supported by this engine yet." errors, internal errors, and an
  unknown identifier that is a real Power BI library function the engine does not implement. Add
  `analytics_studio/m_engine/pbi_library_names.py` with a frozenset of every Power BI M library name, copied into
  code from `docs/plans/2026-11-08-power-query-functions-pbi.txt` (static metadata; app code must not read that
  file at run time). An unknown name that is NOT a Power BI name is a genuine error (Power BI says the same).
- `_add_custom_column`: on `PowerQueryExpressionError` from `compile_expression`, try `compile_m_formula`; if that
  also fails, raise the original error. Evaluate every row with `evaluate_m_formula`; `MFormulaRefused` on any row
  aborts the step with `TransformationError("Custom column formula: <message>")` — never store a guessed value.
  Read how `output_type` is chosen (dialog/controller) and apply the same output-type handling to M results as to
  old-path results; report what you find.
