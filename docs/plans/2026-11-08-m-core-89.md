## Grammar to cover (Power Query M language specification; operator precedence lowest→highest)
- Literals: numbers (`1`, `1.5`, `.5`, `1e3`, `1.5E-3`, `0x1F`), text `"..."` with `""` and `#(tab)`, `#(cr)`, `#(lf)`, `#(cr,lf)`,
  `#(XXXX)` / `#(XXXXXXXX)` hex escapes, `true`, `false`, `null`; keywords `#infinity`, `#nan`, `#date`, `#time`, `#datetime`,
  `#datetimezone`, `#duration`, `#binary`, `#table`, `#shared`, `#sections` (the `#xxx(...)` intrinsics are parsed as calls to an
  identifier named `#date` etc.).
- Identifiers: regular (`Text.Upper`, dotted names are ONE identifier), quoted `#"a b"`, `@x` (inclusive reference), and the
  implicit `_` and `[field]` shorthand inside `each`.
- `let a = ..., b = ... in e` (names may be quoted identifiers; keep order; duplicate names are a SYNTAX-time
  error? No — Power BI reports `Duplicate initializer named 'x'.` as an Expression.Error at evaluation; keep both and let Part B decide).
- `if c then a else b`, `each e`, function literal `(x, optional y as number) as number => e`, `try e`, `try e otherwise f`,
  `try e catch (e) => f`, `error e`, `type <type-expr>`, `e meta e`.
- Records `[a = 1, #"b c" = 2]`, lists `{1, 2..5, "a"}` (ranges), field access `e[f]`, optional `e[f]?`, projection `e[[a],[b]]`,
  item access `e{i}`, `e{i}?`, invocation `f(a, b)`.
- Operators: `or`; `and`; `is` / `as`; `=` `<>` `<` `<=` `>` `>=`; `+` `-` `&`; `*` `/`; unary `+` `-` `not`; `meta`.
  Use the precedence of the M spec ("Operator precedence" table). Comments `//` and `/* */`.
- Type expressions: primitive types (`number`, `text`, `any`, `nullable number`, ...), `{number}`, `[a = number, optional b = text]`,
  `table [a = number]`, `function (x as number) as text`.
