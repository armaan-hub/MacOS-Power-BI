## Why this is harder than it looks
The engine carries every number as a `Decimal` (`analytics_studio/measures.py`); it does not remember whether a value is Int64, double or currency. Power BI answers depend on that type. Do NOT add a type tag to values (huge change, risks every locked result).
Instead write a **static type inferrer** over the parsed expression: `_static_numeric_type(node, model) -> "int64" | "double" | "currency" | "decimal" | "bool" | "text" | "datetime" | "blank" | None`. `None` means "do not know": the test function then raises `MeasureError` (refuse). Refusing is always safe; guessing is not.

## Signature
`ISINTEGER(x)`, `ISINT64(x)`, `ISDOUBLE(x)`, `ISDECIMAL(x)`, `ISCURRENCY(x)`: exactly 1 argument (0 or 2 arguments are errors: refuse). Result is a Boolean. Each function is `True` only when the static type of `x` is its type; `ISINTEGER` is `True` for int64. (Check the JSON: `ISINTEGER(1)` True, `ISINT64(INT(2.5))` True, `ISDOUBLE(2/1)` True, `ISDOUBLE(1000000000000)` False, `ISCURRENCY(1E15)` False.)

## Typing rules (derive from the saved answers; where an expression is not covered by an answer, return `None`)
- Integer literal that fits Int64 -> int64. Integer literal above Int64 max (`9223372036854775808`) -> double. Literals with `.` or `E` -> double. (`1E15` is double.)
- `/` always double. `DIVIDE(a,b)` double. `POWER`, `SQRT`, `EXP`, `LN`, `LOG`, `LOG10`, `PI` -> double. `ROUND`/`ROUNDUP`/`ROUNDDOWN` -> double (check `ROUNDDOWN(2.9,0)` in the JSON). `FLOOR`/`CEILING`/`MROUND`/`INT`/`MOD`/`SIGN`/`ABS` follow the saved answers (e.g. `FLOOR(2.5,1)` is int64, `CEILING(2.5,1)` int64, `INT(2.5)` int64; read the JSON for the rest).
- `+ - *`: int64 with int64 -> int64; any double -> double; currency with currency or int64 -> currency; currency with double -> read the JSON (`CURRENCY(1)*2`, `CURRENCY(1)+1`, `SUM(Facts[Sales])*CURRENCY(1)`).
- `CURRENCY(x)` / `FIXED(x)` / `VALUE("5")` / `CONVERT`: read the JSON.
- Column references: use the model column's declared type (`Facts[Quantity]` int64, `Facts[Sales]` double). `SUM`/`MIN`/`MAX` keep the column type; `AVERAGE` double; `COUNT*` int64.
- BLANK -> its own type (`ISINT64(BLANK())` is False). `TRUE()` -> bool (all five False). Text, date: all five False.
- `IF`/`SWITCH`/`COALESCE`: only when all branches have the same static type, otherwise `None` (refuse).
- A bare column used as the argument outside a row context is a Power BI error (`SUMX(Facts, ...)` inside row context is fine and uses the column's type).
