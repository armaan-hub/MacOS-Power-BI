# Task 65: answers that do not depend on row order (order-free-55)

**Spec:** `tools/parity/task65_order_free_spec.json`.

**Part A (36 rows):** `TOCSV` / `TOJSON` of `LINESTX` / `LINEST`. These refuse with "The row order of this table expression is not modelled". A LINEST table always has exactly one row, so row order cannot matter.
- Answer TOCSV/TOJSON when the table is statically known to have at most one row (LINEST/LINESTX, ROW, and a constructor with one row).
- The column order, header text and number formatting must equal Power BI's. Compare with the spec answers and with the saved TOCSV/TOJSON answers in the batteries.

**Part B (94 rows):** `CONCATENATEX` without ORDER BY. These refuse with "... walks the rows in an order the local engine does not ...".
Answer only when one of these holds:
1. Every row's text is the same value. Order is then irrelevant, e.g. `CONCATENATEX(CALCULATETABLE(Facts,Facts[Region]="East"),MAX("a","b"))` gives `bbb`.
2. The body folds to an expression whose walk the engine already models: `IF(TRUE(),x,y)`, `IF(1,x,y)`, `COALESCE(BLANK(),x,..)` and similar constant-condition folds. Reuse the existing dictionary walk of the folded body's columns, as a plain body would. Example: `CONCATENATEX(ALL(Facts),IF(TRUE(),Facts[Region],1))` gives `EastEastEastWestWestNorth`.

Keep refusing everything else.
