# Task 195: Power BI's Group By dialog

Planned by Claude Opus 5.5 (Team-Planner), coded by Antigravity, fixed, reviewed and tested by Sonnet 5.5 (Team-Thinker).

- Group By now opens a modal dialog, `GroupByDialog`, objectName "powerQueryGroupByDialog", in place of the inline side panel.
- The dialog has two modes:
  - **Basic:** one grouping column and one aggregation.
  - **Advanced:** "Add grouping" and "Add aggregation". Each aggregation has a New column name, an Operation and a Column.
- Operations offered: Sum, Average, Median, Min, Max, Count Rows and Count Distinct Rows. All Rows is shown disabled.
- Switching from Advanced to Basic keeps only the first grouping and the first aggregation.
- The ribbon, the gear-edit path (pre-filled, and it replaces the step) and Insert Step After all open the dialog.
- Step shape: `{"op":"group_by","columns":[...],"aggregations":[{"operation","new_name"[,"column"]}]}`.
- Sonnet fixes:
  - OK is disabled for duplicate result names, for a result name equal to a grouping column, and for duplicate grouping columns.
  - The operation selector reads group_by while the dialog is open, and is restored when it closes. A ribbon routing test needed this.
- Authorised test edit: the group_by row was removed from the lifecycle dialog-fields table.
- New test file: tests/test_ux195_group_by_dialog.py.
- Backlog, HIGH: Table.Group M is emitted without per-aggregation types (`Int64.Type`, `type nullable number`). This needs a VM check.
