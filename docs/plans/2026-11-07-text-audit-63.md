# Task 73: text audit (text-audit-63)

Two audit grids were probed on Power BI. The first is a broad grid of 1,500 text, date/time and logical expressions (scratchpad t73a); it found only 4 real wrong answers. The second is a focused grid of 3,620 collation and BLANK-text expressions (t73b), which found 70.

Spec: tools/parity/task73_text_audit_spec.json.

- **Part A (linguistic matching).** FIND, SEARCH, CONTAINSSTRING and CONTAINSSTRINGEXACT match text linguistically in Power BI, the way Windows CompareString / ICU does.
  - Canonical equivalents match: "e"+U+0301 equals "é". FIND(É, "E"+U+0301) = 1.
  - Expansions match: ß matches "ss". FIND("ß","Strasse") = 5, and SEARCH("SS","straße") = 5.
  - Compatibility forms match: ǅ matches "Dž".
  - The case-sensitive functions (FIND, CONTAINSSTRINGEXACT) still distinguish case. The others ignore case. In all of them a combining sequence matches its precomposed form.
  - The positions Power BI returns are character positions in the searched text, as Power BI counts them: a combining sequence counts as its UTF-16 units. Check against the evidence.
  - The engine's "=" comparison and the collation18 battery already match. Reuse that collation where you can.
- **Part B (BLANK as text).** REPLACE(BLANK(), …) treats BLANK as "" and returns the inserted text. SUBSTITUTE("", old, BLANK()) returns "", not BLANK.
