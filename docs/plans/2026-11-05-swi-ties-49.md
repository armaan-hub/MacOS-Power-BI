**Approach — exact invariance, no guessing:** Power BI's order is SOME permutation of each tie group. If the final
measure result is identical under EVERY permutation of the tie groups, that result is Power BI's answer.
1. In the SWI evaluator, instead of refusing, compute the tie groups (runs of equal keys in `ranked`). If the product of

   analytics_studio/dax_swi_ties.py) holding an index into the permutation list for each SWI call site in
   evaluation order. Default (no driver active) = keep refusing exactly as today.
3. At the top-level measure evaluation entry point (find where a measure's final value is produced and
   LOCAL-REJECT/refusal is surfaced; the scorer path is `tools/score_spec.py`), add a driver: run once; if an SWI tie
   site was hit, enumerate all permutation combinations (cap 720 total evaluations across all sites; more -> refuse),
   re-evaluate the whole expression for each, and answer only if every run returns the identical value (same type and
   value; table results compare row lists exactly). Any run raising an error, or any disagreement -> keep the original
   refusal message.
4. No other refusal is relaxed. The rule is generic: it never inspects the expression's shape.
