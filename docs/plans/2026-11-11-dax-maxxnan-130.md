# Task 140 — dax-maxxnan-130: MAXX / MINX over a Variant body with NaN beside numbers

Goal: answer more MAXX/MINX shapes whose Variant body gives NaN on some rows and numbers on others, and remove the
old wrong answers on fresh probes. Power BI's running extreme keeps the first value it visits when NaN is involved.

Spec: 202 refused saved answers (75%), holdout 70 (25%), five fresh hidden Power BI sets of 540 expressions each.

Rule found (Sonnet 5.5, fitted on hidden 1-2 and spec, confirmed on hidden 3-5 and holdout):
- An IF / IF.EAGER / SWITCH(TRUE(),...) body is walked branch by branch: rows taking the first branch first, the else rows
  last, each group in the source walk order (dictionary order over stored tables, source order over INTERSECT / EXCEPT).
- Literal-dead branches (FALSE(), 1=0, 0) add no walk columns; a condition that reads no column regroups nothing.
- Refused: IF/SWITCH inside arithmetic or nested in a branch, SWITCH on a value, a text condition that reads a column.
