# Task 111 (Iteration 200): M scripts the step editor cannot map run on the M engine (m-script-101)

Today the M editor (`power_query_m.parse_m_query_script`) turns a script into the app's structured steps and rejects
anything it cannot map. With all M function families done, such a script can instead run on the M engine.

## Part A — engine gaps (`analytics_studio/m_engine/table_fns.py` etc.)
- `Table.TransformColumnTypes` conversions from text/number/logical/date to number, Int64, text, date, datetime,
  time, logical, Currency, Percentage, duration (en-US default; the measured `culture` cases; anything unmeasured is
  an explicit refusal). Errors are lazy cell errors exactly as measured (`DataFormat.Error`, `Expression.Error`).
- `Table.Pivot` with an aggregation function (List.Sum/Count/Max and custom), null handling as measured.
- Spec `engine_cases` (169 live answers; exact equality of `evaluate_to_text`). Current: 25 exact.

## Part B — app wiring
- New transformation op `{"op": "m_script", "script": <full let..in text>, "source_binding": <name>}` in
  `transformations.apply_transformations`: the M engine evaluates `script` with `<source_binding>` bound to the input
  candidate as a typed M table (cells via `m_custom_column.cell_to_m` and the Task 110 types in effect; the binding's
  own expression in the script is NOT evaluated). The result must be a table; convert it back to an
  `ImportCandidate` (headers, rows via `m_to_cell`, column types from the M table type mapped to the app's type
  names). Anything not representable (nested table/list/record cells, unmapped types, engine refusal) aborts the step
  with `TransformationError` — never a guessed value. Genuine M cell errors become `PowerQueryCellError` cells.
- `column_types_after_steps` must report the m_script step's output types.
- M editor: when `parse_m_query_script` cannot map the steps after the source step, return the source step(s) plus
  one `m_script` step holding the whole script (the source binding name is the step the app's source occupies).
  `steps_to_m_script` must regenerate the same script text for an m_script step, so the editor round-trips.
  Save, reopen and refresh must work (`project.py` validation accepts the op).
- Spec `scripts` (32 live answers): each is a full script over `source_table`; build the candidate from the raw text
  rows with the Changed Type types (see Task 110 tests), run the m_script step with `source_binding` "Source", and
  compare the resulting table (headers, column types, cells) with Power BI's canonical table — exact, or the step
  refused; wrong 0.

## Tests
- `tests/test_m_engine_eval.py`: new class for `engine_cases` (exact-or-ERR, minimum exact count).
- `tests/test_m_script_step.py` (new): the 32 scripts; editor fallback produces an m_script step and round-trips;
