### Part F: MOD quotient limit (253 wrong, the biggest Part)
Power BI's MOD(x, d) is the error "An argument of function 'MOD' has the wrong data type or the result is too large or too small." exactly when |x / d| is too large. That depends on the quotient, not on |x|:
- `MOD(1.1E12*d, d)` works and `MOD(1.2E12*d, d)` errors, for d = 1, 7, 0.5, -3, 1E-3, 0.25.
- `MOD(1125899906844*d, d)` works and `MOD(1.126E12*d, d)` errors. The limit lies between 1,125,899,906,844 and 1.126E12. Refuse that band, and error at or above 1.126E12.
- `MOD(1E15,1E10)` = 0, `MOD(1E15,888.5)` = 249 and `MOD(-1E15,888.5)` = 639.5 all work. `MOD(2E15,888.5)` and `MOD(1E17,1E4)` error.
- **This replaces Task 22's stand-in rule "MOD of |x| >= 1E15 is the error".** Find that rule (`dax_math.py` / `measures.py`, search for MOD and `1E15`) and replace it with the quotient rule.
- `MOD(x,0)` stays the division-by-zero error. `MOD(CURRENCY(500000000000),0.25)` errors and `MOD(CURRENCY(200000000000),0.25)` does not; this follows the same rule.
- Values below the limit keep today's arithmetic, which already matches the spec rows.

### Part D: FLOOR, CEILING, QUOTIENT, INT of huge doubles (25 wrong; 235 refused, which may stay refused)

- `FLOOR(4.6E18,3)` = `CEILING(4.6E18,3)` = 4599999999999989760. A candidate rule that fits 5 of 6 measured rows is r15(floor(r15(x/s)) * s), where r15 = nearest double to the value printed at 15 significant digits. `FLOOR(4.6E18,7)` = 4599999999999998976 does not fit it yet. Find the rule that fits every spec row, or refuse the rows it does not settle.
