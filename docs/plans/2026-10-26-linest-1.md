## Semantics (ordinary least squares)
- Returns a one-row table. `y` and `x_i` are expressions evaluated per row of the table (`LINESTX`) or column references (`LINEST`; expressions other than column references are an error: refuse).
- `const` (last argument, optional): `TRUE()` (default) fits an intercept; `FALSE()` forces it through the origin and then there is no `Intercept` and no `StandardErrorIntercept` column.
- Result columns in this order (check the `TOCSV` header lines in the JSON): `Slope1..SlopeN`, `Intercept`, `StandardErrorSlope1..N`, `StandardErrorIntercept`, `CoefficientOfDetermination`, `StandardError`, `FStatistic`, `DegreesOfFreedom`, `RegressionSumOfSquares`, `ResidualSumOfSquares`. A column that does not exist in a variant is an error when referenced (`[StandardErrorSlope2]` with one x, `[Intercept]` with const FALSE).
- With const FALSE the R-squared, F and degrees of freedom use the uncentred formulas (`FStatistic` 8897.66 in the first battery example). Reproduce the JSON numbers; do not assume Excel's LINEST output order.
- Rows where y or any x is BLANK are skipped (check the Facts examples: `Facts[Sales]` has a blank row). Text in x is an error (refuse).
- Too few rows (1 row with intercept, fewer rows than coefficients) and a singular design (perfectly collinear x) behave as the JSON shows; if the JSON says error, refuse.
- Numeric tolerance of the gate is `1e-9 * max(1,|a|)`; use `float`/ordinary least squares via the normal equations or QR; compare against the JSON to confirm (the `ResidualSumOfSquares` example shows `0.0099999999999998`, float noise is fine).
