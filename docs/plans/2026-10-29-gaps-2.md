## Part A: an iterator over an empty table still checks its expression (about 104 of the 120 on the standard table, 118 of the 142 on N)
`SUMX`, `AVERAGEX`, `COUNTX`, `COUNTAX`, `PRODUCTX`, `MEDIANX` and `CONCATENATEX` over a table with no rows return BLANK here without looking at the row
expression. Power BI validates the expression when the query is compiled, so a name that does not exist is an error whether or not a row would have read it.
`MAXX` and `MINX` already do this; look at how, and extend the same check to the others.

Errors in Power BI (all shapes are in the battery; the table is empty in each):
- a bare `[c]` that is neither a column of the walked table nor a measure: `SUMX(FILTER(Facts,FALSE()),[c])`, `SUMX(CALCULATETABLE(Facts,Facts[Region]="Nowhere"),[c])`,
  `SUMX(TOPN(0,Facts,Facts[Quantity]),[c])`, `SUMX(EXCEPT(Facts,Facts),[c])`, `SUMX(FILTER(Facts,Facts[Quantity]>100),Facts[Quantity]+[Nope])`;
- the same under `KEEPFILTERS(...)`;
- a column added by `ADDCOLUMNS` is a column of the walked table (`[z]` after `ADDCOLUMNS(...,"z",1)` is fine) but a column that `SELECTCOLUMNS` did not keep is not
  (`SUMX(SELECTCOLUMNS(FILTER(Facts,FALSE()),"z",1),[Sales])` is an error, `[z]` is not).
Keep what already works: the same expressions over a table **with** rows are errors here today (they match), and a valid expression over an empty table is BLANK
(`SUMX(FILTER(Facts,FALSE()),Facts[Quantity])`, `...,1)`, `...,Facts[Region]="East")`). The rule to implement: the expression is resolved against the columns of the
table the iterator walks (computed columns included) and the measures of the model, empty table or not.

## Part B: a column against COUNTROWS of a table is typed, not valued (16 on the standard table, 24 on N)
`Facts[Region]=COUNTROWS(CALCULATETABLE(Facts,Facts[Region]="East"))` (a text column against a whole number) is an error in Power BI whatever the table holds:
COUNTROWS has the static type Integer. The app decides from the **value**: when the table is empty COUNTROWS is BLANK here and a BLANK takes the type of the other
side, so the comparison runs and answers BLANK or a count. Fix it where the comparison is type-checked: the static type of `COUNTROWS(...)` is a whole number
(also inside `FILTER`, `SUMX(IF(...))` and a `VAR`). A number column against COUNTROWS of an empty table is fine; the battery has both.
The text column against COUNTROWS of a table with rows is already an error here (it matches); keep it.
