# Get Data source catalog

## What appears

The picker groups sources under File, Database, Power BI, Microsoft, Online Services, and Other. The All view combines those categories and collapses duplicate labels.

The catalog lists sources and marks the workflows implemented in this app. Excel Workbook, Text/CSV, XML, JSON, Folder, Parquet, SQLite database, SQL Server, OData Feed, and Web start workflows. Power BI semantic models, OneLake catalog, Dataverse, and the remaining connector entries are informational; their connection workflows are not implemented.

## Implementation status

- **Excel Workbook:** opens legacy `.xls` and modern `.xlsx`/`.xlsm` workbooks; users can select a worksheet and one-based header row. The default is the worksheet with the strongest tabular-data score and its likely header row. Formulas are not recalculated; stored formula results are imported when present. `.xls` dates use the workbook's 1900/1904 date system; ambiguous or invalid date serials remain numeric. Password-protected files and macro execution are not supported. The `.xls` reader is xlrd ([package and format scope](https://pypi.org/project/xlrd/2.0.2/), [date conversion behavior](https://xlrd.readthedocs.io/en/stable/api.html)).
- **Text/CSV:** lets users choose delimiter, encoding, and whether the first row contains headers. Quoted separators and embedded newlines are supported. Blank and duplicate headers are normalized; short rows are padded and extra cells become additional columns.
- **JSON:** accepts a non-empty top-level array of flat objects with scalar values. Columns follow first-seen key order. Nested objects and arrays, duplicate object keys, and non-array roots are rejected.
- **XML:** accepts one repeated record tag under the root with identical ordered scalar child fields. Attributes, nested or mixed content, irregular fields, and multiple record groups are rejected.
- **Shared file preview:** CSV, Excel, JSON, XML, and Parquet show row and column counts and the first 100 rows before import. If the file is already linked to a table, the final Import data action warns that it will replace that table. Canceling or a parse error leaves the current project unchanged.
- **Import limits:** source files are limited to 10 MiB; `.xlsx`/`.xlsm` workbook parts are limited to 80 MiB total uncompressed; tables are limited to 100,000 rows, 512 columns, and 500,000 cells. Oversized files are rejected instead of truncated. These defensive limits have not been benchmarked as performance guarantees for the minimum supported Mac.
- **Parquet:** imports one local `.parquet` file through the shared file preview and linked-source lifecycle. PyArrow reads flat scalar columns in batches; values become text and nulls become blank. Nested, binary, extension, and non-finite numeric fields are rejected. Limits are 10 MiB compressed input, 80 MiB row-group uncompressed data, 80 MiB rendered text, and the existing row/column/cell limits. Runtime acceptance is pending. Cloud locations, partitioned directories, and typed schema retention are not implemented.
- **SQLite database:** opens local `.db`, `.sqlite`, and `.sqlite3` files read-only, lists tables and views, and previews a selected object before importing it. Blank/duplicate headers are normalized, nulls become blank strings, scalar values become text, and BLOB values are rejected. Each selected object is saved as an independent linked table; reopen, refresh, and recent-source routes retain its table/view choice. Limits are 10 MiB database plus optional write-ahead log, roughly 10 seconds per SQLite table query, 100,000 rows, 512 columns, 500,000 cells, and 80 MiB rendered UTF-8 text. Runtime acceptance is pending. This does not connect to SQL Server or other remote databases.
- **SQL Server:** connects directly by host, TCP port, database, and SQL username/password through Microsoft's ODBC Driver 17 or 18. It lists tables/views, previews up to 100 rows, then imports the selected object into the local project. Passwords stay in macOS Keychain; the project stores a credential reference and connection/object settings. Connections always use TLS with certificate validation. SQL `NULL` becomes blank, scalar values become text, booleans use `TRUE`/`FALSE`, dates and times use ISO text, and binary, XML, unbounded text, unsupported, and non-finite values are rejected. Limits are 100,000 rows, 512 columns, 500,000 cells, 1 MiB per cell, and 80 MiB rendered UTF-8 text; login attempts time out after 8 seconds and metadata/table commands after 10 seconds. Saved sources reopen and refresh; they are excluded from Recent Sources. Runtime acceptance against an installed Apple Silicon ODBC driver and live SQL Server is pending. Windows/Entra authentication, generic ODBC, DirectQuery, query folding, and Service/gateway refresh are outside this increment. Install the driver separately using [Microsoft's macOS guide](https://learn.microsoft.com/en-us/sql/connect/odbc/linux-mac/install-microsoft-odbc-driver-sql-server-macos?view=sql-server-2017).
- **OData Feed:** connects anonymously to an HTTPS OData v4 service root, reads the JSON service document, lists entity sets, previews a selection, follows same-origin `@odata.nextLink` pages, and saves the service root/entity selection for reopen and refresh. Redirects and page links stay on the original HTTPS origin with certificate validation enabled. Flat scalar fields only; nested properties and empty entity sets without inferred columns are rejected. Limits are 10 seconds per request, 10 MiB per response, 100 MiB total response data, 100,000 rows, 512 columns, 500,000 cells, 1 MiB per cell, and 80 MiB rendered UTF-8. Anonymous authentication only; Basic, Windows, organizational sign-in, and custom headers are not implemented. Runtime acceptance against a live endpoint is pending.
- **Web:** connects by anonymous HTTPS GET and discovers static HTML tables, flat JSON record collections, or a CSV, XML, Excel, or Parquet resource. Excel uses its recommended worksheet automatically; this workflow has no worksheet picker and does not support PDF. Users preview the selected object; CSV also offers delimiter, encoding, and header controls. The full URL and navigation options are saved for project reopen and refresh. Redirects must stay on HTTPS and TLS certificates are validated. Each response is limited to 10 MiB and requests time out after 10 seconds; common row, column, cell, and rendered-text caps apply. Credentials, cookies, custom headers, POST, browser-rendered JavaScript, pagination, and secret storage are not implemented. Runtime acceptance against public endpoints is pending. - **Folder:** combine matching CSV, Excel, JSON, or XML files from one local folder. Filter by file type and filename text, optionally include subfolders, configure parsing through a sample file, preview the combined rows, and report a schema mismatch with the filename. An optional `Source.Name` column is enabled by default. Refresh reruns the saved folder recipe. The selection is limited to 500 matching files and 100 MiB combined source size; each file is limited to 10 MiB, and combined rows/cells use the existing limits. Save/reopen and refresh behavior are implemented in code; runtime acceptance is pending.
- **PDF:** remains visible but unavailable.
- **OneLake catalog and Dataverse:** remain visible as informational connector choices; their connection workflows are not implemented. Generic ODBC entries do not connect; the implemented SQL Server path is specific to SQL Server's Microsoft ODBC driver.
- **Other entries:** remain selectable for information, but do not start connections or authentication.
- **Recent sources:** keeps a bounded, deduplicated list in application settings. Selecting an existing file, including Parquet, opens the shared preview and confirmation flow; a folder reopens the folder selection and preview with its saved recipe. Missing files/folders are identified and disabled. Refresh reloads only the active linked source.
- **Insert menus:** More visuals, custom-file visuals, Buttons/Navigator, and Shapes are unavailable until their report-object workflows are implemented.
