**Audit date:** 2026-10-12

**Status:** Partial implementation; complete Power Query Desktop parity is not claimed.

## DAX and semantic-model target

Microsoft's [DAX function reference](https://learn.microsoft.com/en-us/dax/dax-function-reference) documents more than 250 functions across scalar, filter, relationship, table, statistical, text, financial, time-intelligence, and other families. Analytics Studio currently recognizes 50 names in a bounded Python evaluator; all 50 have partial semantics, and the evaluator is not a complete Tabular model/query engine. The count is an inventory, not a compatibility score. A `RELATED` form supports numeric target values through one direct active many-to-one relationship inside table iterators. Numeric keys use typed equality; text keys use the shared Unicode case-fold comparer used by relationship filtering and one-side uniqueness, because model collation is not stored. Locale-specific behavior may differ; case-fold collisions on a one side reject during relationship validation and refresh. Calculated-column lookup, inactive/multi-hop relationships, and general DAX behavior remain unsupported. Full DAX remains gated on a viable Mac-compatible runtime and a semantic oracle; see the [DAX compatibility contract](DAX_COMPATIBILITY_CONTRACT.md) and [ADR 0001](docs/adr/0001-dax-runtime-and-semantic-oracle.md).

## What Analytics Studio currently implements

### Separate native editor session

`TransformDataDialog` is a separate native Qt window with six ribbon tabs, a Queries navigator, Query Settings for query names, descriptions, groups, and saved-query load/refresh switches, per-query Applied steps, a selected-step table preview, a formula bar for representable single-line steps, column quality/profile tabs, and a separate Advanced Editor window reachable from both Home and View. Home's Advanced Editor action opens the same editor with the active query/session state. The Transform tab includes Detect Data Types, which applies inferred changes as replayable conversion steps. Import uses the same conservative inference on file, Web, OData, and SQL Server candidates; Transform Data starts from that same inferred type map so an unrelated edit cannot reset types to text. The session and Advanced Editor use a high-contrast light surface in macOS dark mode. The View ribbon exposes a selected-step Schema tab and a read-only dependency diagram. A supported standalone or embeddable Mashup runtime API for this app has not been identified; that is narrower than saying no M engine exists on macOS. Steps and query properties remain isolated while switching queries. Close & Apply validates the staged query results and applies changes in one project transaction; newly staged Append/Merge are rebuilt from their accepted parent previews and checked against the shown preview. Cancel leaves the project unchanged.

The current session refreshes local file and in-memory sources when it opens, then builds included query previews in dependency order. An excluded saved query keeps its last evaluated source/result in the session, so changed upstream data cannot silently refresh it; included dependents continue from that cached result. Editing an excluded query's own steps is allowed. Query name and description edits persist; renaming a loaded query also renames its model table and rewrites matching references in supported saved DAX objects. Saved queries can disable/enable model load and report refresh in Query Settings; disabling the active query switches to another loaded source when available. The session refreshes raw snapshots after successful Apply and rejects previews whose source or output no longer matches.

Duplicate Query stages an independent ID with the selected source/query definition, transformations, and query metadata. Delete Query stages removal and Close & Apply commits the project/model/cache changes atomically after checking dependencies. Query names released by a deletion can be reused by a new query in the same Apply. A failed non-active query remains in the navigator with its preview error; its editing commands are disabled while deletion remains available from the Queries pane context menu.

Selecting an Applied Step updates the table/profile to the state after that step; clearing the selection returns to the final result. The formula bar can edit supported single-line expressions for the selected step. The visible gear button, right-click **Edit Settings…**, and double-click open a modal settings page initialized from the selected operation. **Save** validates a replacement step and replays its downstream steps before updating the preview; **Cancel** restores the selected step's controls without accepting edits. Operations without editable settings disable the gear and context-menu item. These pages use the local operation controls; they do not claim every Power Query Desktop transform or engine behavior. Unsupported steps and multiline expressions are routed to the separate Advanced Editor, which remains a bounded M subset. Column quality and profile support all-table or first-100-row scope. Blank values are excluded from distinct, unique, and top-value counts; error counts are explicitly marked **Not tracked** because the local normalized-text model does not retain cell-level errors.

### Local transformation engine

The local engine validates and replays 46 step kinds against normalized text cells. Its operation inventory is maintained in `analytics_studio/transformations.py` and includes:

| Group | Operations |
|---|---|
| Columns and filters | Rename/remove/keep/reorder columns; simple and advanced filters; duplicate handling; blank-row removal |
| Types and ordering | Type conversion and locale conversion; single and multi-column sort |
| Text and delimiter work | Replace, trim, clean, lowercase, uppercase, proper-case, reverse, before/after/between extraction, delimiter split, split-to-columns/rows, fixed-position split, merge |
| Reshape and aggregate | Group By, pivot, selected/other-column unpivot, transpose |
| Add columns and fill | M-subset custom column, conditional column, duplicate column, index column, Fill Up/Down |
| Row windows and headers | Keep/remove top/bottom/range/alternate rows; promote/demote headers |

Type detection is a separate command rather than a new step kind. It samples at most 200 rows to choose a candidate type and validates every nonblank value before adding `convert_type` steps; fields that look like identifiers (for example TRN, voucher numbers, or leading-zero keys) remain text. Numeric/date cells are still stored as normalized strings with a model type map, so this does not add typed cells, cell-level conversion errors, or Power Query's full type-detection behavior.

Other data workflows in the app include saved append/merge/reference query definitions, query name/description/group, load/refresh flags, typed scalar parameters, reusable one-argument scalar functions, source refresh, save/reopen, and changed-source replay. The Home ribbon stages local files/folders and SQL Server/OData/Web root sources, plus Reference, Append, and Merge queries. New remote roots use their existing connector dialogs, stage in the open session, and commit their source/model/type/data records together on Close & Apply; canceled sessions do not write them. Append currently accepts two inputs with identical ordered columns; Merge supports its listed exact-match join kinds and one or more key pairs. The View ribbon opens a read-only dependency diagram with source-to-query arrows. Cancel leaves the project unchanged. Parameter values can be edited in Manage Parameters and selected in simple/advanced row-filter controls; supported M comparisons preserve the parameter name. A new reference computes once on Apply even when later report refresh is disabled; subsequent Refresh All preserves its cached result. Duplicate/delete are lifecycle-tested session actions; deleting an unused SQL Server source removes its Keychain entry. General M functions, query privacy, SQL Server/OData/Web source editing and broader source settings, broad credential management, query folding, and a general M runtime remain open.

**2026-10-12 Applied Step settings update:** Configurable steps now have a visible gear beside the Applied Steps controls, as well as the context-menu and double-click entries. The settings page starts with the saved values for that operation. Save replays the full ordered transformation sequence; invalid edits stay in the page with an error, while Cancel restores the saved values. Steps with no settings disable the gear. Automated acceptance covers Filter Rows, Change Type, Split Column, Replace Values, and Custom Column, plus cancel, invalid/save, downstream replay, save/reopen, and changed-source refresh. Manual macOS appearance and accessibility acceptance is still open.

### Advanced Editor boundary

The Advanced Editor does not run Microsoft’s Mashup engine. `power_query_m.py` parses a safe, linear `let … in` subset referencing the current query and translates supported calls into the same local step list. User text is not executed as Python. The current parser/emitter handles fewer operations than the transform engine.

Supported local M shapes currently include selected/remove/rename/reorder columns; single and multi-condition equality, comparison, blank, positive text, and guarded negative text filters; multi-condition filters preserve the local AND-before-OR rule and reject groupings the local step model cannot represent; numeric comparisons convert text values with `Number.From` and guard null/empty cells before conversion; remove blank rows; custom text columns; bounded Conditional Column if-chains; type conversion including a literal-culture `Table.TransformColumnTypes` form for whole/decimal number, date, datetime, and time; single/multi-column sorting; duplicate removal and retention by selected text keys; first/last/skip/range/alternate row windows; Group/Pivot/Unpivot; replace value; common text transforms; delimiter extraction, first/every-delimiter split, fixed-position split through `Splitter.SplitTextByPositions`, split-to-rows, merge, and the one-argument `Table.Transpose` form; promote/demote headers; integer index and duplicate columns; and fill down/up. Conditional Column supports ordered literal/column outputs, representable equality, six null-guarded text predicates, and ordered numeric comparisons only after explicit numeric conversion. Numeric equality, text equality against another column or the empty string, and text predicates with column-valued search terms are rejected because local string storage cannot preserve the required numeric/null distinctions. Empty-string search terms use a guard that matches the local blank behavior. Locale-aware conversion accepts only a literal culture string and the local type subset, then validates/canonicalizes culture names through the existing local conversion validator. Whole-number conversion with or without a culture uses M default ties-to-even rounding and signed Int64 bounds; decimal-number conversions reject Double overflow and normalize underflow to signed zero. Currency.Type is rejected because fixed-decimal semantics are not represented by the local number type. Delimiter extraction accepts numeric zero-based occurrences and explicitly maps null and empty inputs to empty text. First-delimiter splitting uses one literal `Splitter.SplitTextByEachDelimiter` and keeps the remainder in the second output; every-delimiter splitting computes its output width from the current table, with a minimum of two columns. Split defaults are explicitly empty text to match this app's normalized-text model. Split-to-rows accepts only a null-coalesced `Text.Split` list followed by `Table.ExpandListColumn`; dynamic width uses the same null-coalescing rule. Merge accepts `Combiner.CombineTextByDelimiter` with `QuoteStyle.None`. Text inputs must remain text-typed: numeric values introduced by Unpivot are rejected unless explicitly converted to text; `List.Min`/`List.Max` preserve that type marker through Group; text operations after Pivot are rejected because Pivot creates nullable, data-derived columns; and steps after Promote/Demote Headers require an explicit text conversion before a text-only operation; cell-dependent operations after Transpose are blocked. Custom M columns must have a text-producing expression; non-text conversions such as `Text.From` must happen in the expression itself, and a text type annotation alone does not convert a numeric result. M string and quoted-field escapes inside custom expressions are decoded before local replay. Relative-from-end delimiter indexes, quote-aware splitting, arbitrary split transforms, non-text merge/extract/split inputs, and general null/error fidelity are outside this subset. `Table.RemoveLastN`, `Table.Range`, and `Table.AlternateRows` map to local row-window steps with optional counts bounded by the 100,000-row ceiling. `Table.Group` is limited to local sum, average, median, min, max, row count, distinct-row count, and distinct-value count forms. After `Table.Transpose`, the bridge only permits schema projection/rename/reorder, row windows, index creation, and the exact null-or-empty blank-row removal pattern; value-dependent transformations are blocked because the local model cannot preserve native cell types or distinguish null from empty text. `Table.Pivot` must derive categories from the current step's attribute column and supports the local aggregation forms. Custom-column output is normalized to text, and the emitter uses `Text.From`. The fixed-position mapping follows Microsoft's [documented M positions](https://learn.microsoft.com/en-us/powerquery-m/splitter-splittextbypositions) and is restricted to numbered output names and the local empty-text default. This is a local operation matrix, not broad M-language coverage.

The bridge has the following material limits:

- Keep Duplicates now round-trips through a canonical grouped composite-key expression. It is limited to text-typed keys, uses [ordinal comparison](https://learn.microsoft.com/en-us/powerquery-m/comparer-ordinal), explicitly maps M nulls to the local empty-text representation, and restores row order with a generated index because [Table.Group does not guarantee output order](https://learn.microsoft.com/en-us/powerquery-m/table-group). This matches the app's normalized-text step behavior; it does not preserve a distinction between null and empty text when an external M source contains both. Conditional Column round-trips the tested predicate/output subset; text predicates require an explicit null guard and ordered numeric comparisons require a prior numeric type conversion. Negative text-filter variants also round-trip with an explicit null guard and are rejected after a non-text conversion. The `Table.Transpose` bridge accepts only its one-argument form; optional output-column names are not supported. After transpose, value-dependent M operations, including Group, filtering, distinct, sorting, type/text transforms, pivot/unpivot, and fill/replace, are rejected because local normalized text loses native cell types and merges null with empty text. Schema-only changes, row windows, index creation, and the exact blank-row removal pattern remain supported. Locale-aware type conversion is limited to a literal culture string and the five supported local type families listed above; culture records, text/logical culture conversions, and Currency.Type are rejected.
- Both Advanced Editor entry paths now check the entire saved sequence and report every numbered unrepresentable step before opening. The button remains enabled and the blocked path leaves query state unchanged.
- The editor clears any cached preview when code changes or fails. Apply re-parses and replays the current script, so a stale successful candidate cannot be committed after an invalid edit.
- Single and multi-column sort directions and the `number` type alias now round-trip canonically. `Table.Sort` accepts a column name with default ascending direction, explicit `Order.Ascending`/`Order.Descending`, and mixed criteria. Rename targets and sort criteria are parsed strictly.
- `Table.AddIndexColumn` accepts its default start/increment and signed integer values; fractional/null values and types other than `Int64.Type` remain outside this local subset. Non-text result types for `Table.AddColumn` and `Table.TransformColumns` are rejected instead of discarded.
- Custom-column M expressions use `Text.From` to match the local text-cell output for supported scalar expressions. The parser checks known input types for text/numeric calls, and rejects a numeric result or invalid nested call even when wrapped in `Text.From`. Escapes in expression strings and quoted column references decode before replay. There is no Microsoft Mashup runtime in the test suite, so generated scripts are checked against the local parser/step engine, not externally executed for full M semantic equivalence. Null and empty values are still collapsed by the local model.
- Supported authored M text is stored as optional query metadata and restored only when it still parses to the saved local steps. Refresh continues to execute the validated local step list; a query rename or step edit invalidates mismatched authored text.
- A table-driven matrix now compares direct local execution to M-export/reparse execution, including output and type maps, for every operation shape currently emitted. It does not establish equivalence with Microsoft's Mashup engine or cover all 46 local transformation kinds.
- The local candidate stores cells as normalized strings; source null/empty/error values are not represented as distinct Power Query values.
- No general M evaluation, arbitrary source expression, query folding, source privacy settings, general credential manager, multi-argument or nested M functions, or parameter use outside supported filters and custom-column formulas is provided. SQL Server uses connection-bound Keychain credentials; OData and Web remain anonymous.

## Ordered implementation roadmap

### P0 — M bridge safety — complete for the current subset

- `m_compatibility_issues` derives representability from the serializer/parser and reports every blocker by position and operation.
- Transform Data and direct Advanced Editor entry use the same report; the command stays enabled and blocked entry leaves the query unchanged.
- Script changes and failed previews invalidate cached candidates; Apply only accepts a successful replay of the exact current script.
- Canonical sort/type aliases, default/mixed sort criteria, strict rename/sort syntax, index defaults/signed values, custom-column and text-transform type handling, and generated `Text.From` output are covered by focused regression and table-driven output/type-map tests.
- One-clause advanced filters canonicalize to their equivalent simple-filter shape so a safe script can be previewed, applied, and matched to the saved steps without being falsely rejected.
