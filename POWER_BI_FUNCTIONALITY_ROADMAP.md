# Power BI Functionality Map and Whole-Product Roadmap

**Research date:** 2026-10-08. **Purpose:** Expand the import-only schedule into a map of Power BI's major user-facing and platform capabilities, show what Analytics Studio already supports, and estimate a sensible implementation order.

## Scope

Power BI is a collection of products and services: Desktop authoring, the Power BI service in Microsoft Fabric, mobile consumption, paginated reporting, administration, and developer/embedding surfaces. This document is the master A-to-Z map of those product capability families, not just data import. The linked Microsoft Learn catalogs provide the exhaustive connector, visual, and API inventories, whose availability changes by product, license, tenant, region, and capacity.

Analytics Studio is an independent native desktop app, currently targeted at Apple Silicon Macs. The roadmap describes comparable functionality to build into this app; it does not turn it into Microsoft's Power BI Desktop or provide PBIX compatibility by itself.

### Large local-file preview parsing — background progress and cancellation implemented

CSV, JSON, XML, and Parquet previews parse on a worker when the source is at least 256 KiB. Excel and SQLite option discovery and preview parsing always run on workers, including small compressed workbooks and databases with a large WAL file. An indeterminate progress bar shows that work is active and row-count messages advance during large reads. The dialog Cancel action sets a cooperative event checked during Excel archive/sheet scans, SQLite catalog reads, and parser loops. Changing parser options cancels the old preview and ignores stale results. The project is updated only after the completed candidate is accepted.

Acceptance in [test_file_import.py](</Users/armaan/Power BI tool/tests/test_file_import.py>) verifies parser progress and cancellation plus an Excel recommendation cancellation checkpoint. [test_import_lifecycle.py](</Users/armaan/Power BI tool/tests/test_import_lifecycle.py>) verifies off-UI Excel/SQLite discovery, event-loop responsiveness, cancel requests, stale-result suppression, worker parsing, progress display, and preview completion. On the current Apple M5 Pro host, a 10,000,010-byte CSV with 100,000 rows and 5 columns parsed in a median 0.109 seconds across five worker-path runs; a 2,357,312-byte `.xlsx` with the same row/column shape parsed in a median 1.545 seconds across three default-preview runs. The minimum supported Mac is M1; timing on M1 remains pending.

### `CALCULATE` — Boolean column filters, replacement, and `KEEPFILTERS`; acceptance passed

`CALCULATE(expression)` evaluates the expression in the current filter context when no row context is active. ### Table-valued `FILTER` in `CALCULATE` — bounded subset; acceptance passed

The evaluator accepts one direct `CALCULATE(scalar_expression, FILTER('LoadedTable', predicate))` argument over one loaded base table. Inequality operators also work when the scalar literal appears on the left.

`FILTER` reads the target table's currently visible input rows, including current direct and supported relationship filters. | 98+ (separate track) | Fabric and Power Platform | Add Dataflow Gen2, OneLake/Direct Lake, Power Apps/Automate, Fabric Apps and translytical task flows (preview), and Fabric Real-Time Intelligence. | Each Fabric workload has a capacity, authentication, and data-lifecycle design; avoid new dependencies on streaming models scheduled to retire. |
| 98+ (separate track) | AI and advanced analysis | Add Q&A/Copilot, supported AI visuals, and additional analysis experiences when tenant and capacity prerequisites are met. | Privacy, licensing, tenant controls, model readiness, and output review are defined. |

This is a **low-confidence, order-of-magnitude scenario**, not a delivery commitment. It is roughly **two years or more** for one developer to reach the broad local-authoring and cloud-service foundation; the post-core extension tracks are open-ended and have no individual effort estimate yet. Re-estimate after architecture and prototypes, then rank each track by user demand and dependencies. Mobile, paginated reporting, an M-compatible query engine, full DAX compatibility, every connector, and deeper Power BI/Fabric parity can extend it by years. The import-only stages are detailed separately so local-first work can ship without waiting for the cloud platform.

## Recommended delivery strategy

1. Ship the local data/model foundation and core report-authoring workflows first; it delivers value without requiring service infrastructure.
2. Decide explicitly whether Analytics Studio is expanding into a multi-user cloud service before starting workspaces, publishing, sharing, or scheduled refresh.
3. Prioritize connectors by user demand and implement them individually with documented authentication and supported modes.
4. Treat full M, broad DAX compatibility, PDF/OCR, DirectQuery, live connections, and Direct Lake as dedicated engineering projects with prototypes and revised estimates.
5. Keep every visible control tied to a working workflow or show it as unavailable, consistent with the current project roadmap.
