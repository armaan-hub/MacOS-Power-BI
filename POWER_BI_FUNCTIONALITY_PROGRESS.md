## Overall status

Analytics Studio has working local data-import, query-shaping, and semantic-model foundations. Work is still in progress: broad report authoring, service collaboration, governance, and platform capabilities remain open. This roadmap describes Power BI-comparable capabilities for Analytics Studio; it does not make the app Microsoft Power BI or provide PBIX compatibility.

The source-settings workflow covers existing CSV, Excel, JSON, XML, Parquet, SQLite, folder, SQL Server, OData, and Web roots. Remote editors restore the current connection and navigation options, stage the replacement preview, and preserve source identity and applied steps. SQL Server passwords remain session-only until Apply and are saved under a new connection-bound Keychain reference when the connection or password changes. Included query descendants refresh from the staged preview; excluded queries retain their cache. Column-name or type changes are still rejected, and automated lifecycle acceptance for remote edits has not yet been recorded. Local edits retain the existing SQLite binding and relationship checks. Schema migration remains open.

The roadmap graph mixes summary stages with individual capabilities, and its previous aggregate counts and 78% figure were stale. They are withdrawn: a graph-box ratio is not a useful measure of whole-product parity. Use the tested scopes and open acceptance gates below.

New sources retain parser/navigation options, can feed staged Reference/Append/Merge queries, and commit their source and model records with the previewed data. Local files are freshness-checked on Apply; explicitly refreshed remote sources use the snapshot the user reviewed. SQL credentials are connection-bound in Keychain and rolled back if a later staged credential write fails. Web URLs with common token-like query parameter names are rejected. Cancel and failed Apply preserve project state. DAX measure authoring adds bounded `COUNTX` and `COUNTAX` iterator forms with numeric, text, Boolean, blank, empty-string expression, and simple `IF` coverage; iterator conditions type-check supported expressions recursively. Equality/inequality supports matching numeric, Boolean, or text types; ordered comparisons require numeric operands. Typed text cannot be treated as Boolean inside logical or `IF` iterator conditions, numeric functions and `COUNT` reject typed text inputs, and nested iterators use their own table schema even when their rowset is empty. Scalar aggregations resolve their column types in their own model table. A bounded `RELATED` form returns numeric target values through one direct active many-to-one relationship inside a table iterator, ignores lookup-table filters, and returns blank for unmatched keys. A shared relationship comparer uses typed numeric equality and Unicode case-folding for text keys across `RELATED`, relationship filtering, and one-side uniqueness checks. Case-fold collisions on a one side reject during relationship validation and changed-source refresh. The project does not store locale-specific model collation. `RELATED` target values must be numeric. The local evaluator now recognizes 50 functions, all still partial. Stored empty cells and `BLANK()` results are skipped; formula-produced empty strings count. `COUNTX`/`COUNTAX` now return blank when no countable result exists, preserve blank through tested measure/report paths, and keep numeric zero distinct. `DISTINCTCOUNT` counts the local blank marker and returns blank for an empty rowset; the bounded `DISTINCTCOUNTNOBLANK` counterpart is available in the measure and Quick Measure editors. Operator-specific blank coercion and complete DAX semantics remain open. Automated tests confirm tested local behavior, not Power BI-wide parity or full manual application acceptance.

Manage Parameters supports typed text, whole-number, decimal, boolean, date, and datetime values in simple/advanced row filters, supported M comparisons, and the safe custom-column expression subset; save/reopen, preview, and source refresh resolve current typed values. Successfully previewed supported M text survives Apply and project save/reopen; refresh still replays validated local steps. The bridge does not run Microsoft's Mashup engine. Keep Duplicates accepts text keys and cannot preserve an external null/empty distinction. Conditional rules support a bounded predicate subset. After transpose, cell-dependent M operations are rejected because normalized text loses native cell types. General M functions, parameter use outside supported filters and custom-column formulas, query privacy, broader credential management, remote edit acceptance, query folding, and a Mashup runtime remain open.
